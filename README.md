# RoboGround

**面向服务机器人的开放词汇 3D 场景理解与语言接地系统。**
从 RGB-D 视频流建出带语义的 3D 地图，再用自然语言查询它。

`Python` · `PyTorch` · `ROS2 Humble` · 全链路**零下载可跑** · **570 个测试**全绿

---

## 这是什么

给机器人"**看懂**（3D 场景理解）"和"**听懂**（语言接地）"两件事：

- **看懂** —— 用开放词汇检测 / 分割 / 图文编码把像素升到 **3D 特征场**（存特征而非类别 id，
  所以任意文本都能查 3D），再用**跨帧实例关联**把多帧观测串成"物体"；
- **听懂** —— 查询走"词法 + 嵌入"双路匹配，几何规则引擎算精确米制答案，
  VLM 只在几何做不到的地方补语义（**语义归 VLM、度量归几何**）；
- **落地** —— 封装为标准 **ROS2 ament 包**：`colcon build` → `ros2 launch`，
  参数可在线调，位姿走标准 TF 树。

旁路还有一条**数据与后训练**链路：视频管线 + 大规模语料工程 + GRPO/RLVR + Qwen2-VL LoRA 微调。

## 快速开始

```bash
pip install -e ".[dev]"

python scripts/00_quickstart.py     # 零下载跑通全链路（约 10 秒）
pytest                              # 570 个离线测试（约 13 秒，无需 GPU）
pytest -m slow                      # 另 24 个真实数据测试（需 SUN RGB-D）
```

启用真实开放词汇后端（可选，权重约 2.6 GB）：

```bash
pip install -e ".[perception]"
python scripts/09_test_real_backends.py --steps all --encoder siglip
```

ROS2 部署（WSL2 + Humble）：

```bash
cd ros2_ws && colcon build --packages-select roboground_ros && source install/setup.bash
ros2 launch roboground_ros full.launch.py static_tf:=true
```

## 系统架构

```
  RGB-D 帧 ──► 开放词汇 2D 感知（Detector → Segmenter → Encoder，可插拔 + 离线降级）
                   │
              ┌────▼─────────────────────────────────────────┐
              │ 几何层：反投影 2D → 3D 世界系（内外参 / 幽灵点过滤） │
              └────┬─────────────────────────────────────────┘
                   │ Observation(points_world)
              ┌────▼─────────────────────────────────────────┐
              │ Stage 2 · 3D 语义地图（核心）                   │
              │   ① 跨帧实例关联  ② 体素特征场  ③ 物体层+体素层  │
              └────┬─────────────────────────────────────────┘
                   │ SemanticMap
              ┌────▼─────────────────────────────────────────┐
              │ Stage 3 · 语言查询 + 空间推理                   │
              │   词法/嵌入双路匹配 · 规则引擎 · VLM（事实约束+幻觉闸门）│
              └────┬─────────────────────────────────────────┘
                   │
              Stage 4 · 部署：量化 / ONNX / 异步快慢分级 / ROS2

  Stage 5（旁路）：视频管线 → 大规模语料工程 → 自动标注闭环 → 后训练（LoRA / GRPO）
```

## 已知局限（摘要）

完整清单见 [`docs/项目完整清单与阅读顺序.md`](docs/项目完整清单与阅读顺序.md) 与各报告末节。
把最重要的几条放在这里：

1. **没有真机联调** —— 所有验证都是合成场景或 rosbag 回放，**这是唯一真正缺的一环**（需要硬件）。
2. **快档达不到 640×480 @ 10 Hz** —— 单帧 133~148 ms（纯 Python 实现，体素融合占 64%）；
   320×240 是 42~47 ms（上限 21~24 Hz），10 Hz 下余量只有约 2.2 倍，**属于能力边缘**。
3. **离线模式的"开放词汇"是词法匹配** —— 真开放词汇必须用 SigLIP/CLIP 后端；
   且当前基准的 10 个类别全在别名表内，对词法路径天然有利。
4. **VLM 给不出可用的米制数值** —— 微调后 3D 坐标误差仍有 1.35 m。
   这是单张 RGB 的数学限制，所以架构上必须"语义归 VLM、度量归几何"。
5. **跨模态对齐（字幕↔画面）未真正执行** —— 代码里会**显式声明**未执行，
   所以"字幕与画面无关"这类噪声只被检出存在、还没被过滤。
6. **镜头检测金种子只覆盖 6 条视频（0.2%）** —— F1=0.947 说明判据方向正确，
   不能外推为全数据集指标；渐变（叠化）检测没有人工真值。
7. **★ 多视角融合只做到"真实多视角的一部分"** ——
   旧做法是把 SUN RGB-D 的**单帧**点云**重渲染**成"多视角"（无效深度像素从 **42.8% 升到 77.0%**），
   收益微弱且非单调，旧说法"−52%"经核查是**单个场景的偶然结果**、已作废；
   那条链路（`virtual_camera.py` + 脚本 26/27）**已整体删除**，
   历史记录见[核查报告](docs/多视角数据核查报告.md)。
   现在换成 Stanford 2D-3D-S 的**真实多视角 → 一张 360° 全景**，与官方全景逐像素一致；
   但**天顶 / 天底从未被观测**（全景只是约 ±55° 的水平环带），
   也还没产出与单帧同口径的定位误差对比 —— 见[全景融合报告](docs/多视角全景融合报告.md)。
