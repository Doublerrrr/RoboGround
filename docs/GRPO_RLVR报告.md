# GRPO + 规则引擎可验证奖励（RLVR）报告

> 面向岗位画像补强的第三环：**RL 后训练**。
> 复现：
> ```bash
> python scripts/18_train_grpo_spatial.py --dry-run                    # 离线自检（不用 GPU）
> python scripts/18_train_grpo_spatial.py --steps 8 --g 4 \
>   --init-adapter runs/vlm_spatial_lora_full/epoch2 --temperature 1.2
> ```
> 代码：`src/roboground/rl/`（reward / grpo / torch_loss / trainer）
> 测试：`tests/test_grpo.py`（38 个）

## 零、核心思路：把"几何规则引擎"变成 verifiable reward

RLVR 在数学/代码领域能 work，是因为有**确定的答案校验器**（对答案、跑单测）。
多模态空间推理通常**没有** —— 只能训 reward model，而 reward model 会带来 reward hacking。

**但本项目有一样别人没有的东西**：几何规则引擎能从 3D 语义地图算出**精确答案**。

```
3D 地图 ──规则引擎──> 精确真值 (1.70, 0.00, 0.85)
VLM 输出 "杯子在 (1.74, 0.04, 0.85)"
reward = exp(-||Δp|| / τ) = 0.96        ← 可验证、不可 hack、无需训 reward model
```

这就是把"主观生成 RL 的 reward 怎么设计"落地的答案：
**先问一句"这个任务能不能自动验证"，能验证的就不要训 reward model。**

## 一、奖励设计（三层）

| 层 | 形式 | 解决什么 |
|---|---|---|
| **格式门控** | 0/1，不过则总分 0 | 输出不可解析 → 后续无从判定 |
| **正确性** | **塑形**（连续） | 见下 |
| 长度惩罚 | 轻微负分 | 防止用"啰嗦"刷格式分 |

### ★ 为什么数值任务必须用塑形而不是二值奖励

二值奖励（"误差 <0.3m 给 1"）在 RL 早期几乎恒为 0：
**基座模型的坐标误差是 2.756 m**，离 0.3 m 十万八千里 → 整组全 0
→ 组内优势全 0 → **梯度为 0，完全学不动**。这就是**稀疏奖励**问题。

塑形 `exp(-|Δ|/τ)` 虽然分都不高，但**排序正确**：
误差 2.7m 得 0.004、1.3m 得 0.074、0.4m 得 0.45 —— 组内就有相对优势。

实测（`--dry-run` 的对照）：用塑形奖励时组内优势**不再退化**，
而二值/格式分在同样场景下会退化成全 0。

> τ 的选取：与"可接受误差"同量级。距离 τ=0.5m（可接受 0.3m），
> 坐标 τ=1.0m（坐标误差天然更大，实测 1.35m vs 0.42m）。
> τ 太小有效梯度区间过窄，太大区分度不足。

### ★ 冷启动：正则兜底路径

如果只认 JSON，RL 早期整组格式分全 0 → 优势退化 → 学不动。
所以 `parse_answer` 留了一条**正则兜底**：说人话但说对了也能拿部分正确性分。

但**必须把两条路径分开统计** —— 实测踩过：
`format_rate` 一直是 1.00，看起来"模型很听话"，
其实基座模型根本没写 JSON，是正则把任何含数字的文本都判成"可解析"。
所以新增了 **`json_rate`** 指标专门统计真正走 JSON 路径的比例。

## 二、GRPO 实现要点（面试深挖的部分）

目标函数全部**手写**（环境里没有 `trl`），并且拆成**可单测的纯函数**。

### 2.1 组内优势（GRPO 砍掉 value network 的关键）

```
A_i = (r_i - mean(r_1..r_G)) / (std(r_1..r_G) + eps)
```

PPO 需要 value network 估基线，GRPO 用"同 prompt 采 G 个样本、组内均值当基线"。
代价是每 prompt 多采 G 次，收益是省掉一个与策略同规模的 value network，
且**天然适配可验证奖励**（不需要学 value，只要能判对错）。

### 2.2 Clip 的作用与对象

**对象是"新旧策略的概率比"，不是奖励也不是优势**（最常见的错误答案）。

| 优势 | 比率情形 | 结果 |
|---|---|---|
| A > 0 | `r` 超 `1+ε`（好动作概率涨太猛） | 截成 `(1+ε)·A` |
| A > 0 | `r` 低于 1（好动作概率在跌） | **不截**，继续给梯度 |
| A < 0 | `r` 低于 `1-ε`（坏动作概率跌太猛） | 截成 `(1-ε)·A` |
| A < 0 | `r` 高于 1（坏动作概率在涨） | **不截**，继续惩罚 |

**只在"策略已经很努力往正确方向走"时停止加码**，往错方向走时继续给梯度。
这保证单调改进的下界。

> ⚠️ 我第一版把这个说反了（注释写成"A<0 时不截断"），
> 是被单测里 `obj = (1-ε)·A = -0.8` 而不是 `-0.5` 抓出来的。
> 所以四条分支都写成了断言。

### 2.3 KL 散度：三个估计器

| 估计器 | 公式（`d = logp_ref - logp`） | 特点 |
|---|---|---|
| `k1` | `-d` | 无偏但**方差大**，单样本可为负 |
| `k2` | `d²/2` | 恒非负、方差小，但**有偏** |
| **`k3`** | `exp(d) - 1 - d` | **无偏且方差最小**，实践默认 |

⚠️ 关键事实（容易说错）：**k1 与 k3 都是无偏的**，差别在**方差**不在期望。
因为 `E_{π_θ}[exp(d)] = Σ π_θ·(π_ref/π_θ) = 1`，所以 `E[k3] = KL`。
我用蒙特卡洛（20 万样本、离散分布对）验证了两者均值都收敛到真实 KL，
且 k3 的标准差显著更小。

> 我第一版写成"三者应逐样本相等"，也是被测试直接打脸。

### 2.4 Token 级 vs Sequence 级 IS（GSPO 的动机）

- **token 级**（GRPO 原版）：逐 token 算比率 → 同一序列里各 token 比率可能
  一个 2.0 一个 1.0，**clip 之后目标函数不再对应"整条回答的好坏"**。
- **sequence 级**（GSPO）：长度归一化后整条序列共享一个比率，
  语义一致、**对 MoE 更友好**（MoE 路由放大逐 token 方差，序列级把方差摊平）。

实测（dry-run 第 ③ 项）：序列内逐 token 比率 `[2.0, 2.0, 1.0, 1.0]`
vs 整条序列 `[1.414]`。

### 2.5 Clip-higher（熵坍塌的处置）

对称 clip 下低概率 token 的比率容易被**上界**截住 → 永远拿不到正梯度
→ 策略越来越确定 → 熵塌掉、输出单调。
把**上界放宽**（0.28 vs 下界 0.2）给低概率 token 留上升通道。

⚠️ 是放宽**上界**而不是下界 —— 放宽下界会让坏样本更容易被学。

## 三、★ 实测踩到的两个致命坑

这两个坑的共同特点是：**日志看起来一切正常，但训练完全没发生**。

### 坑 1 · `top_k=1` 让采样退化成贪心 → 梯度恒为 0

**现象**：GRPO 每一步的组内优势都是 0，`loss=0`、`grad=0`，一个字都学不到。

**定位过程**：
1. 先怀疑奖励设计 → 打出**逐组奖励**，发现每组 G=4 个样本奖励**完全同分**；
2. 再怀疑模型 → 打出**逐组原始回答**，发现 4 个回答**逐字符相同**：
   ```
   resp[0] = 'The center distance between the monitor and the bottle is 1.'
   resp[1] = 'The center distance between the monitor and the bottle is 1.'
   resp[2] = ... （完全相同）
   ```
3. 隔离诊断：换不同随机种子各生成一次，看输出是否变化 —— **1/3 种输出（确定）**。

**根因**：Qwen2-VL 自带的 `generation_config.json` 里是
```json
{"do_sample": true, "temperature": 0.01, "top_p": 0.001, "top_k": 1}
```
`top_k=1` = 只保留概率最高的那一个 token，采样**直接退化成贪心解码**。
而且传 `temperature` / `top_p` **覆盖不掉它** —— 必须显式给 `top_k=0`。

隔离验证：

| 配置 | 3 次输出不同数 |
|---|---|
| `T=1.4, top_p=0.95` | **1/3**（确定） |
| `T=1.4, top_p=1.0` | **1/3** |
| `T=1.0, top_p=0.9` | **1/3** |
| **`T=2.0, top_p=1.0, top_k=0`** | **3/3**（真随机） |

**修复后**：`grad` 从恒为 0 变成 **0.216~0.921**，
组内退化率从 **100% 降到 0~67%**。

> 这个坑值得讲的地方是：**RL 需要"多样性"这句话，落到工程上是一个非常具体的
> `top_k` 参数**。而且它不会以任何报错的形式出现 ——
> reward 数值正常、loss 正常、程序不崩，只是梯度恒为 0。
> 唯一能发现的办法是把**逐组原始回答**打出来看。

### 坑 2 · 冷启动：基座模型不会探索，必须先 SFT

修好 `top_k` 之后还有一个问题：**直接用基座模型跑，组内仍然大量退化**。
原因是基座没在这个输出格式上 SFT 过，答案分布本身就很集中。

这正是面试里问的「GRPO 的**冷启动问题**」。
标准解法是 **SFT → RL 两段式**，于是改成从已有的 SFT adapter 继续：

```
--init-adapter runs/vlm_spatial_lora_full/epoch2
trainable params: 9,232,384 || 0.4162%     ← 与 SFT 阶段一致
```

## 四、实测结果

**配置**：Qwen2-VL-2B + LoRA（4bit），从 SFT epoch2 继续，
G=4、temperature=1.2、inner_epochs=2、44 条 RL 样本、8 步、**278 秒**。

| step | reward | correct | loss | **grad_norm** | 组内退化 | json 率 |
|---|---|---|---|---|---|---|
| 1 | 0.644 | 0.444 | −0.0028 | 0.263 | 33% | 0% |
| 2 | 0.375 | 0.175 | −0.0032 | 0.400 | 33% | 0% |
| 5 | 0.657 | 0.457 | −0.0051 | **0.921** | 33% | 0% |
| 6 | 0.344 | 0.144 | −0.0040 | 0.733 | **0%** | 0% |
| 8 | 0.722 | 0.522 | −0.0008 | 0.436 | 33% | **17%** |

- **reward**：前 3 步均值 0.448 → 后 3 步均值 **0.650**
- **梯度**：`mean 0.462`（修复前**恒为 0**）
- **组内退化率**：均值 38%（修复前 **100%**）
- **json 率**：0.00 → **0.17**（格式遵循度开始上升）

> ⚠️ **诚实的边界**：8 步 × 3 prompt × G=4 = 96 次采样，规模很小，
> reward 的上升**不能作为收敛证据**（波动很大，且每步抽的 prompt 不同）。
> 这一轮的真正产出是**把链路打通并证明了梯度真的在流动**，
> 以及**定位到两个"训练静默失效"的坑**。要谈效果必须跑完整评测集。

## 五、离线自检（`--dry-run`，不用 GPU，几秒钟）

这是"先证明逻辑对，再花 GPU 时间"的做法 —— 用 `FakePolicy` 跑通整条循环：

| 对照 | 结果 |
|---|---|
| ① 难度偏差 | 正确率 0.0/1.0 → 优势退化 **87.5% / 93.8%**；0.5 → 仅 **6.2%** |
| ② IS + Clip | `inner_epochs=1` → ratio **1.0000**、clip **0.0000**（死代码）<br>`inner_epochs=3` → ratio **1.3771**、clip **1.0000** |
| ③ token vs seq IS | 序列内 `[2.0, 2.0, 1.0, 1.0]` vs 整条 `[1.414]` |
| ④ reward hacking 诊断 | 只写 JSON 答错 → 格式 1.0 / 正确 **0.0**（信号）<br>答对但格式自由 → 0.200 → **1.200**（正则兜底救了它） |

**②特别值得讲**：`inner_epochs=1` 时策略根本没变过，ratio 恒为 1，
**clip 是一段死代码**；≥2 次内层更新才会让比率偏离 1。
这解释了"为什么 PPO 需要多次内层更新"。

## 六、面试答题稿

**Q：主观生成的 RL，Reward 怎么设计？**

> 我的思路是先问一句：**"这个任务能不能自动验证？"**
> 能验证的，就不要训 reward model —— reward model 会带来 reward hacking，
> 而且要和策略一起迭代，工程成本高得多。
>
> 空间问答恰好能验证：我项目里的几何规则引擎能从 3D 地图算出精确答案。
> 于是 reward = 格式门控 × 正确性（塑形）。三个设计要点：
>
> 1. **格式门控**卡住"乱写也有分"，但必须留**正则兜底** ——
>    否则 RL 早期整组格式分全 0 → 优势退化 → 完全学不动（冷启动）。
> 2. **数值任务必须用塑形奖励**。二值奖励在早期几乎恒为 0
>    （基座坐标误差 2.76m，离 0.3m 十万八千里），整组全 0 → 梯度为 0。
>    这就是**稀疏奖励**。塑形奖励虽然分不高，但**排序正确**，组内就有相对优势。
> 3. **奖励必须逐项记录**。只看 total 无法诊断 reward hacking ——
>    "格式分涨、正确性分不动"意味着学会了写 JSON 但没学会答对。

**Q：你 RL 训练踩过什么坑？**

> 两个，共同点是**日志看起来完全正常，但训练根本没发生**。
>
> 第一个是 `top_k=1`。我第一次跑 GRPO，每一步的组内优势都是 0、梯度恒为 0。
> 一路查下来：先打逐组奖励 → 发现组内 G=4 个样本奖励完全同分；
> 再打逐组原始回答 → 发现 4 个回答**逐字符相同**；
> 最后隔离验证换随机种子跑 3 次 → 输出完全一样，说明**采样根本没在随机**。
> 根因是 Qwen2-VL 自带的 `generation_config.json` 里 `top_k=1`，
> 只保留概率最高的 token，采样退化成贪心，而且传 `temperature`/`top_p`
> **覆盖不掉**，必须显式给 `top_k=0`。
> 修完之后梯度从 0 变成 0.2~0.9。
>
> **这件事让我记住：RL 里"策略要有探索"不是一句口号，
> 落到工程上就是 `top_k` 这种具体参数；而且它失效时不会报任何错。**
>
> 第二个是**冷启动**。修好采样之后，直接用基座模型跑，组内还是大量退化 ——
> 因为基座没在这个输出格式上 SFT 过，答案分布本身就很集中。
> 这就是 GRPO 的冷启动问题，标准解法是 **SFT → RL 两段式**。
> 我改成从已有的 SFT LoRA 继续，组内退化率就从 100% 降下来了。

**Q：GSPO 和 GRPO 的区别？**

> 核心在 **Importance Sampling 的层级**。
> GRPO 是 **token 级**比率：逐 token 算 `π_θ/π_old`，
> 于是同一个序列里各 token 的比率可能一个 2.0 一个 1.0，
> **clip 之后目标函数就不再对应"整条回答的好坏"** —— 这就是
> 面试里说的"Token/Sequence 不一致"。
>
> GSPO 改成 **sequence 级**：先把整条序列的 log 概率和做**长度归一化**，再取指数，
> 整条序列共享一个比率。三个好处：
> ① 语义一致；② 对 **MoE 友好**（MoE 路由会放大逐 token 方差，
> 序列级把方差摊平）；③ 长度归一化避免长回答的比率被系统性低估、被 clip 误伤。
>
> 我实现里 `level="token"|"sequence"` 是个开关，
> 单测验证了同一个 batch 下两者损失确实不同（否则说明开关没生效）。

## 七、诚实的边界

1. **训练规模极小**（8 步 / 96 次采样），reward 上升**不能当收敛证据**。
   这一轮的产出是"链路打通 + 梯度确实在流 + 定位到两个静默失效的坑"。
2. **没有做 RL 前/后的完整评测对比**。要谈"RL 提升了多少"，
   必须在 `scripts/14_eval_vlm_spatial.py` 的评测集上跑 SFT vs SFT+RL 对照。
3. **没有用参考模型**（β=0）。KL 惩罚的代码路径已实现并单测，
   但真实训练里没启用（省一份前向的显存与时间）。
4. **inner_epochs 偏小**，clip 几乎没被触发（clip_frac ≈ 0）。
   要观察 clip 行为需要更多内层更新。
5. **reward 的塑形会引入偏好偏差**（模型可能学会"输出看起来接近的垃圾"），
   所以必须配格式门控，且 τ 不能乱设。
