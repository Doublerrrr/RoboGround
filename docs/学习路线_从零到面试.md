## 零、先看权重：为什么不该按代码量学

全项目代码量分布（`find src -name '*.py' | xargs cat | wc -l`）：

| 模块 | 行数 | 面试是否问到 |
|---|---|---|
| `data/`（视频管线 + 大规模语料工程） | **7,324** | ✅ **问得最多** |
| `perception/`（S1 开放词汇） | 2,535 | ⚠️ 间接（Special Token / CLIP） |
| `mapping/`（S2 3D 语义地图） | 2,143 | ❌ 基本没问 |
| `deployment/`（S4 量化 / ONNX / ROS2） | 2,168 | ⚠️ 只问了 vLLM prefix caching |
| `rl/`（GRPO + RLVR） | **1,330** | ✅ **7/16 道题** |
| `reasoning/`（S3 空间推理 + VLM） | 1,315 | ⚠️ 问了 CoT / 幻觉 |
| `geometry/`（地基） | 1,240 | ❌ 没问 |
| `eval/` | 736 | ⚠️ Agent 评测 |
| `utils/` | 342 | ❌ |

**结论：`rl/` 只有 1,330 行，却对应 7 道题。`geometry/` + `mapping/` 加起来 3,279 行，一道题都没问到。**

所以路线是：**L0 全貌 → L4 数据工程 → L5 RL + 部署 → L2 地图 → L3 语言 → L1 几何**。
前三讲覆盖面试绝大部分权重，后三讲是你的"底气"（面试官一旦问"你这系统怎么串起来的"，
只有理解后三讲才答得上来）。

## L0 · 全貌（本讲，约 15 分钟）

**目标**：能用一句话说清项目是什么，能画出五阶段管线。

- 一句话：给定「RGB-D 视频流 + 一句自然语言」，输出目标物体在 3D 世界系中的**米制坐标**与空间关系。
- 五阶段：S1 感知 → **S2 建图（核心）** → S3 推理 → S4 部署 → S5 数据闭环。
- 单帧旅程（必须背）：彩色+深度帧 → 2D 检测分割 → 反投影+位姿 → 跨帧实例关联+体素融合 → 语言查询。

**动手**：
```bash
conda activate lxr && cd G:\RoboGround
python scripts/00_quickstart.py      # 全离线端到端，10 秒
```
看完输出，你就有了"这个系统跑起来长什么样"的直观印象。

**自测**：
1. 为什么"抽帧"的语义单位是**镜头**而不是秒？
2. S2 的输入和输出分别是什么？（`types.py` 里的 `Observation` → `SemanticObject`）

## L4 · 数据工程（★ 面试权重最高，建议第 2 个学）

**目标**：能完整讲"一条视频从落盘到进训练集，中间被砍掉多少、为什么砍"。

**核心概念**（对应面试官原话「大规模多模态数据处理」+「视频怎么切帧」）：
1. **视频切帧的判据链**：HSV 联合直方图 → 卡方距离 → robust 阈值 → **峰值突出度判据** → 硬切/渐变 → NMS → 最短镜头长度；
2. **抽帧预算固定而非按比例**：按内容变化率分配，不按时间长度；
3. **两级去重**：dHash（感知哈希）→ 嵌入余弦；
4. **四道质量闸门**：过曝 / 欠曝 / 模糊 / 低对比；
5. **三级字幕去重**：精确重复 → 词集 → MinHash + LSH；
6. **温度配比**：`p_i ∝ n_i^α`（α=0.5），防止大类刷屏。

**对应代码**：
- `src/roboground/data/video/shot.py` — 镜头检测（本讲最重要）
- `src/roboground/data/video/sampling.py` — 四种抽帧策略
- `src/roboground/data/video/filter.py` — 去重 + 质量闸门
- `src/roboground/data/corpus/` — 数据集级语料工程

**动手**：
```bash
python scripts/21_shot_diag.py --videos video7014      # 看帧差曲线 + 阈值 + 边界
python scripts/24_goldset_eval.py                      # 四阶段指标
pytest tests/test_video_pipeline.py -v                 # 30 个测试
```

**自测**：
1. 为什么不能用 Otsu 定阈值？（答：真实帧差是**重尾单峰**，Otsu 的前提双峰不成立）
2. 「帧间差异大」能区分"切镜头"和"镜头内快运动"吗？（答：不能，幅度上无法区分，要靠**形态**——突出度差三个数量级）
3. 只测召回率有什么问题？（答：这个缺陷在只看召回时完全看不出来，召回一直是 1.000）

**面试怎么讲**：见 `docs/大规模多模态数据工程报告.md` 第四节 —— 讲"我发现了什么缺陷、怎么定位、怎么验证修好了"，比讲"我处理了多少数据"有效十倍。

## L5 · RL 后训练与部署（★ 7/16 道题在这里）

**目标**：能讲清 GRPO 的完整数据流，以及"主观生成任务怎么设计 Reward"。

**核心概念**：
1. **RLVR（可验证奖励）**：不是训一个 reward model，而是用**规则引擎**直接判对错 —— 因为空间关系任务的正确性可验证；
2. **三层奖励**：格式门控（不合格直接 0）→ 塑形正确性 → 长度惩罚；
3. **组内优势（GRPO 核心）**：同一个 prompt 采样 G 个回答，用组内均值/标准差算 advantage，**不需要 critic**；
4. **重要性采样比 + clip + KL**：`ratio = exp(logp - logp_old)`，clip 到 `[1-ε, 1+ε]`，KL 约束别跑偏；
5. **量化 / ONNX**：数值对齐校验（不能只看"能导出"）；
6. **异步快慢分级流水线**：丢帧而不是阻塞。

**对应代码**：
- `src/roboground/rl/reward.py` — 三层奖励
- `src/roboground/rl/grpo.py` — 组内优势 / IS / clip / KL
- `src/roboground/rl/torch_loss.py` — torch 版 loss
- `src/roboground/deployment/quantization.py` / `export_onnx.py`

**动手**：
```bash
python scripts/18_train_grpo_spatial.py     # GRPO 训练（含 FakePolicy 离线自检）
python scripts/07_export_onnx.py            # ONNX 导出 + 数值对齐
```

**自测**：
1. GRPO 相比 PPO 去掉了什么？为什么可以去掉？（答：critic / value model，因为组内采样本身就是 baseline）
2. 为什么要做 KL 约束？KL 系数调大调小分别会怎样？
3. "主观生成任务"（比如开放式 caption）怎么做 RL？（答：规则引擎不适用时，要用**可验证的子维度**拆解，或引入裁判模型 —— 这是面试官追问的点）

**面试怎么讲**：见 `docs/GRPO_RLVR报告.md` 与 `docs/面试答题稿_VLM与RL.md`。

## L2 · 3D 语义地图（项目的地基，约 40 分钟）

**目标**：能讲清"跨帧实例关联"这个最难的问题。

**核心概念**：
1. **为什么不能靠空间聚类构建物体** —— 相邻的两个杯子会被并成一个；
2. **实例关联**：靠 2D 框的 IoU + 特征相似度 + 3D 距离三重判据，跨帧把同一物体的观测串起来；
3. **体素特征场**：`mean` / `max` / `conf_weighted` 三种聚合方式；
4. **地图级定位误差**是主要质量指标（不是单帧误差）。

**对应代码**：`src/roboground/mapping/builder.py`（`MapBuilder`）、`semantic_map.py`。

**动手**：
```bash
python scripts/03_build_map.py       # 真实 SUN RGB-D 建图
python scripts/05_benchmark.py       # 出定位误差数字
```

**自测**：
1. 地图级定位中位误差：合成 0.218 m / 真实单帧 0.381 m / 6 个渲染视角 0.259 m（★ 旧"虚拟相机"重渲染链路与其产物**已删除、不可复现**，仅作历史记录）—— **注意**：旧版写的「0.553 → 0.262，−52%」经核查不成立（单场景偶然结果 + 两批场景混用），详见 docs/多视角数据核查报告.md。现在的多视角路线是 2D-3D-S 的**真实多视角 → 一张 360° 全景**（docs/多视角全景融合报告.md）。

## L3 · 语言：开放词汇查询 + 空间推理（约 40 分钟）

**目标**：能讲清"词法路径"和"嵌入路径"的分工，以及为什么必须同时测**拒识**。

**核心概念**：
1. **双语别名表**：反向索引必须**多对多**（一个词对应多个物体）；
2. **词法 vs 嵌入**：词法命中就是 1.0、不命中就是 0，**所以阈值不能低**（踩过坑：0.05 导致 27.8% 未见类别误命中）；
3. **空间关系**："旁边(near)"只能在**水平轴**判断；
4. **规则引擎保底 + VLM 增强**（HybridReasoner）。

**对应代码**：`src/roboground/mapping/query.py`、`src/roboground/reasoning/`。

**动手**：
```bash
python scripts/16_eval_openvocab_query.py    # 未见表达命中 + 未见类别拒识
python scripts/04_query_demo.py
```

**自测**：
1. 为什么"只测命中、不测拒识"等于没测？（答：拒识才是开放词汇的真正难点）

## L1 · 几何地基（最后学，但它是理解 L2 的前提，约 30 分钟）

**目标**：理解"像素 → 相机系 → 世界系"的完整变换链。

**核心概念**：
1. 针孔模型与内参（`fx fy cx cy`）；
2. **深度尺度**：SUN RGB-D 的深度要 `/10000` 才是米；
3. **`coeffs` 是全边长不是半边长**（踩过的坑）；
4. 幽灵点过滤（深度为 0 的像素投影到无穷远）。

**对应代码**：`src/roboground/geometry/projection.py`。

**自测**：给定像素 `(u,v)` 和深度 `d`，写出它在相机系下的坐标。
（答：`x = (u - cx) * d / fx`，`y = (v - cy) * d / fy`，`z = d`）
