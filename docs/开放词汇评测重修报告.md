# 开放词汇评测重修报告

> 起因：一位专业 VLM 算法工程师审阅本项目后指出——
> 「**"命名命中 100% / 未见类别拒识 100%"是红旗，不是亮点** ——
> 满分指标通常意味着任务被构造得太简单」。
>
> 这份报告就是去核实那句话。**结论：他说对了，而且实际情况比他推测的更差。**

---

## 一、原评测的三个硬伤（逐条核实）

| # | 问题 | 核实结果 |
|---|---|---|
| 1 | **负样本太简单** | `NEGATIVE_PROBES = ["冰箱","微波炉","马桶","浴缸","**飞机**","**汽车**","**自行车**","helicopter","airplane","bicycle","**submarine**"]` —— 与室内场景毫无关系，**一个颜色直方图都能拒掉**。零难例（无 chair↔armchair 这类语义近邻） |
| 2 | **候选池太小** | 用**合成场景**（`SyntheticRoom`），类别池是 `catalog` 里**写死的 10 类**，默认只用 **6 个物体**。在 6 个候选里做 top-1，100% 几乎不构成证据 |
| 3 | **"100%" 全部来自词法路径** | 词法（别名表）命名命中 **100%**；而真·视觉语言特征（SigLIP）只有 **31.2%**。原报告把两者混在一起报 `hit`，读者会以为是模型能力 |

> 所以"两个 100%"里：**拒识 100% 是白送的**（负样本太简单），
> **命名 100% 是查表得到的**（不是模型能力）。

---

## 二、修复一：加难负样本（合成评测）

在 `scripts/16_eval_openvocab_query.py` 里把负样本**拆成两类**：

- **简单负样本**（保留作对照）：冰箱/飞机/潜艇…
- ★ **难负样本**：与地图内类别**语义高度接近**但地图里确实没有的词，
  且**按场景动态选取**（只有"相邻正类在该场景里、且自己不在"时才用）：

```python
HARD_NEGATIVES = {
    "chair":   ["armchair", "stool", "bench", "扶手椅", "长凳"],
    "sofa":    ["loveseat", "futon", "躺椅"],
    "table":   ["countertop", "workbench", "吧台"],
    "shelf":   ["cabinet", "wardrobe", "locker", "柜子", "衣柜"],
    "monitor": ["television", "laptop", "tablet", "电视", "笔记本电脑"],
    "box":     ["crate", "basket", "篮子"],
    "bottle":  ["jar", "canister", "罐子"],
    "lamp":    ["lantern", "chandelier", "吊灯"],
    "trash can": ["dumpster", "recycling bin"],
    "cup":     ["bowl", "vase", "花瓶", "wine glass"],
}
```

> `armchair` 里**含子串 `chair`** —— 这是**故意**的对抗样本，会直接冲击
> 词法路径的子串规则（0.85 分）。

### 结果（合成场景，SigLIP）

| 模式 | 简单负样本拒识 | ★ **难负样本拒识** | 命名命中 | 描述命中 |
|---|---|---|---|---|
| 词法 | 100% | **73.3%**（116 条） | 100% | 42.9% |
| 嵌入（SigLIP） | 87.5% | **40.5%** | 31.2% | 11.9% |
| 融合 | 100% | **73.3%** | 100% | 42.9% |

**"拒识 100%" → "拒识 73.3%"**：有 26.7% 的语义相邻查询被**错误接受**。
这才是可以写进材料的数字。

## 三、修复二：搬到真实数据（这才是决定性的一步）

合成场景的候选池**上限就是 10**，无法通过调参做大 —— 所以必须换真实数据。
新增 `scripts/40_eval_openvocab_real.py`：

| 维度 | 原评测（合成） | 新评测（真实） |
|---|---|---|
| 图像 | 合成渲染 | **Stanford 2D-3D-S 真实采集** |
| 候选池 | 固定 6~10 | **该房间真实物体数** |
| 负样本 | 飞机/潜艇 | **难例**（armchair ↔ chair 等） |
| 特征 | 颜色直方图/SigLIP | **SigLIP 真特征**（物体图像区域编码） |
| 索引方式 | 体素特征场 | 物体级特征（等价于场里存的那份特征） |

**协议**：正样本 = 池内每个物体的类别名（期望 top-1 命中自己）；
判别力用 **AUC** 与**最佳阈值平衡准确率**（而不是"完全可分"那种过严判据）。

### 结果（12 个采集点，真实全景 + SigLIP）

| 指标 | 实测 | 参照 |
|---|---|---|
| **候选池大小**（min/中位/max） | **12 / 34 / 50** | 合成评测只有 6~10 |
| 类别名 **top-1** | **53.3%** | 随机基线 = 1/34 ≈ **3%** |
| 类别名 top-5 | **89.1%** | |
| 描述型 top-1 | **42.9%** | 真开放词汇泛化 |
| **AUC（简单负样本）** | **0.596** | 0.5 = 纯随机 → **几乎无判别力** |
| ★ **AUC（难负样本）** | **0.352** | **低于 0.5 ⇒ 比随机还差** |
| 平衡准确率（简单 / 难） | 0.690 / 0.581 | 0.5 = 无判别力 |

产物：`runs/40_eval_openvocab_real.json` / `.log`

### ★ 两个必须直面的结论

**1. 连"简单负样本"都分不开。**
合成评测里"简单负样本拒识 100%"，在真实数据上 AUC 只有 **0.596**（≈随机）。
也就是说那个 100% **完全是合成场景太干净**造成的假象，不是能力。

**2. 难负样本上 AUC = 0.352 < 0.5 —— 比随机更差。**
这意味着 `armchair` / `cabinet` / `television` 这类**语义相邻词**在 SigLIP 特征上
得到的相似度**系统性地高于正确类别名**。换句话说：

> **当前的 3D 特征场（哪怕换上真 SigLIP 特征）在真实数据上不具备可用的开放词汇判别力。**

## 四、这对项目叙事的影响（诚实修订）

| 原来的说法 | 修订后 |
|---|---|
| 「开放词汇查询**命名命中 100%**、**未见类别拒识 100%**」 | ❌ **不能这么写**。真实数据上：类别名 top-1 **53.3%**、难负样本 AUC **0.352**；100% 是"词法别名表 + 6 个候选 + 飞机当负样本"三个因素叠加出来的 |
| 「**体素级 3D 特征场**承载开放词汇能力（存特征而非类别 id，任意文本可查）」 | ⚠️ **机制成立，效果不成立**。真 SigLIP 特征在真实物体上判别力接近随机 → 这个卖点目前**没有实测支撑** |
| — | 面试可直接讲**这次的自我否定**：从"两个 100%"查到"候选池只有 6、负样本是飞机"，再重建到真实数据上得到"top-1 53.3% / 难负 AUC 0.352"。**这体现的是评测素养与诚实度**，比一个虚假的 100% 值钱得多 |

### 待办（本报告未完成的部分）

- 特征质量差的原因还没定位：是 **SigLIP 本身不适合细粒度家具分类**、
  还是**物体裁剪太小/被遮挡**、还是**缺少多视角特征融合**？
  需要做消融（裁剪尺寸 / 多视角平均 / 换 CLIP 或 DINOv2）才能定论；
- 与 LERF 类方法的**同评测对比**尚未做（当前连自己的 baseline 都没达标，对比无意义）；
- 「多视角融合能否提升特征质量」是一个**可检验的假设**（融合后覆盖更全、遮挡更少）
  —— 这是本项目**唯一可能站得住的算法贡献方向**，但尚未验证。
