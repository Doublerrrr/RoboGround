# RoboGround 技术方案报告

> 项目：面向服务机器人的开放词汇 3D 场景理解与语言接地系统  
> 目标：给定 RGB-D 视频流与自然语言，输出目标物体在 3D 世界系中的米制坐标  
> 定位：服务机器人"看 → 懂 → 定位 → 规划"链路中的**感知层**

---

## 一、问题定义与难点

### 1.1 形式化

| 项  | 定义                                                    |
| -- | ----------------------------------------------------- |
| 输入 | RGB-D 帧序列 $\{(I_t, D_t, K_t, T_t)\}$ + 自然语言 query $q$ |
| 输出 | 目标物体的 3D 中心 $c \in \mathbb{R}^3$（米）+ 尺寸 + 标签 + 空间关系   |
| 约束 | 端侧实时（感知 ≥10Hz）、8GB 显存、类别集开放、环境未知                      |

### 1.2 三个核心难点

**难点 1：类别开放（open vocabulary）**  
用户可能问任何物体（"那个放饮料的东西"）。封闭集检测器的 label 集合覆盖不了，  
所以必须用**文本与视觉共享空间**的表示（CLIP 范式），  
并且 3D 侧也要存特征而不是类别 id。

**难点 2：环境未知（online mapping）**  
机器人第一次进这间房，没有预先建好的地图。所以必须在线增量建图，  
并具备**多视角融合**能力（同一物体被多帧看到 → 特征平均 → 抗噪）。z

**难点 3：实时性（latency budget）**  
VLM 推理动辄几百 ms~~数秒，而避障需要 10~~30Hz。  
两者不能串在一个循环里，必须**按时间轴分级**。

### 1.3 与纯 2D VLM 的本质差异

| 维度     | 2D VLM        | 本项目（3D 语义地图）                       |
| ------ | ------------- | ---------------------------------- |
| 空间表示   | 像素坐标          | **米制 3D 坐标**                       |
| 能否给规划用 | ❌ 不知道"1.5 米外" | ✅ 直接输出 `geometry_msgs/PoseStamped` |
| 多视角一致性 | 无             | 体素级特征融合天然一致                        |
| 遮挡处理   | 看不到就没了        | 多帧累积可"回忆"                          |
| 推理成本   | 单次几百 ms       | 感知 30ms/帧 + 查询 0.3ms               |

**结论**：机器人动作规划需要**带尺度的语义**，  
而 2D VLM 只给"像素级语义"。所以必须把语义升维到 3D —— 这是本项目的立足点。

## 三、核心算法

### 3.1 开放词汇 3D 特征场

**思路**（OpenScene / CLIP-Fields 范式）：  
把 3D 空间切成边长 $v$ 的体素，每个体素聚合落在它内部的所有像素特征，  
得到稠密的 3D 特征场。查询时用"文本特征 × 体素特征"的相似度定位。

**为什么用体素而不是纯点云**：

1. 点云稀疏冗余（一个物体几万点，语义只有一份）；
2. 体素聚合天然完成**多视角融合**（同体素被多帧看到 → 特征平均 → 抗噪）；
3. 体素键是整数，便于哈希、连通域分析和序列化。

**三种融合模式的取舍**：

| 模式                    | 公式                                           | 适用                      |
| --------------------- | -------------------------------------------- | ----------------------- |
| `mean`                | $\frac{\sum w_i f_i}{\sum w_i}$（$w_i=1$）     | 通用，抑制单帧噪声               |
| `max`                 | 逐维 $\max_i f_i$                              | 保留最显著语义响应（OpenScene 常用） |
| `confidence_weighted` | $\frac{\sum s_i f_i}{\sum s_i}$，$s_i$ 为检测置信度 | 检测质量差异大时                |

**实现要点**：帧内先用 numpy 做一次聚合（`_unique_rows` 用 void 视图压行），  
再把"唯一体素"并入字典。这把 Python 层操作从 $O(N_{点})$ 降到 $O(N_{体素})$。

### 3.2 跨帧实例关联（★核心决策）

**为什么不用空间聚类**：DBSCAN 只看几何距离，  
桌子边上的杯子（中心距离 0.07m < eps 0.08m）会被连进桌子那一簇。

**关联算法**：

```
for obs in observations:
    best = None
    for track in tracks:
        if require_label and not labels_compatible(obs.label, track.label):
            continue
        d = ||obs.centroid - track.center||
        score = 1 - d/assoc_radius          if d <= assoc_radius
        score = IoU(track.bbox, obs.bbox)   elif IoU >= assoc_iou
        best = argmax(score)
    if best is None: tracks.append(new_track(obs))
    else:            best.add(obs)
```

**标签兼容性判定**：复用 `LexicalMatcher` 的别名表——  
"chair" 与 "chair" 兼容，"cup" 与 "table" 不兼容。  
（这一步让"桌上的杯子"不会因为距离近而被并进桌子。）

**轨迹聚合**：用可累加的中间量而不是最终值  
（`points_sum/count` 求中心、`feature_sum/weight_sum` 求特征、  
`label_votes` 投票、有界采样的点集求分位数 bbox）。

### 3.3 空间关系判定

**主轴主导原则**：人描述位置时只说一个主导方向  
（"杯子在桌子上面"，不会说"上面偏右一点"）。

```
1) 包含关系优先：containment_ratio >= inside_ratio → "inside"
2) 计算三轴归一化分离量 norm[i] = Δ[i] / ((size_a[i]+size_b[i])/2)
3) 取 |norm| 最大的轴作为主导轴
4) 若强度 < axis_ratio → 退化为 near / overlapping / unknown
5) 竖直轴(z)：|Δz| >= above_delta → above/below；否则 near/unknown
6) 水平轴(x/y)：先看 bbox_gap <= adjacent_gap → "near"（相邻优先于弱方向）
              否则按符号 → left/right_of 或 in_front_of/behind
```

**为什么用尺寸而非固定阈值做归一化**：  
"两个大柜子相距 30cm"和"两个小杯子相距 30cm"是完全不同的语义。  
用两个物体的平均尺寸做尺度，判断才符合直觉。

**第 6 步的顺序很关键**：只在**水平轴**做"相邻→near"，  
否则"杯子放在桌上"（gap=0）会被误判成"杯子在桌子旁边"。  
（有专门的回归测试守护这条规则。）

### 3.4 语言查询：两路匹配 + 融合

| 匹配器                | 依赖      | 能力                   | 局限                       |
| ------------------ | ------- | -------------------- | ------------------------ |
| `LexicalMatcher`   | 无       | 别名表 + 子串 + 字符 bigram | **不是真开放词汇**，只能匹配别名表覆盖的表达 |
| `EmbeddingMatcher` | CLIP    | 真·开放词汇（任意文本）         | 需要模型与权重                  |
| 融合（hybrid）         | 可选 CLIP | 加权和 + max 兜底         | —                        |

**为什么用 max 兜底而不是纯加权平均**：  
两路分数尺度不可比（词法命中就是 1.0，嵌入相似度通常 0.7~0.9）。  
纯平均会让"词法强命中"被嵌入稀释。

**双语别名表**：~45 个概念 × 中英别名，反向索引必须是**多对多**  
（"桌子"同时属于 table 和 desk）。

### 3.5 意图解析（中文不切词）

**方案**：词表召回而非分词。

1. 词表 = 全部别名 + 地图标签（**全量，不限地图内类别**）；
2. 按长度降序扫描原文，用区间占用避免重复匹配；
3. 提及 → 地图标签的映射保留歧义（返回全部达标标签）。

**7 类意图优先级**：`distance > list_on > count > nearest > relation > locate > describe`

**关键设计**：判定"用户问了几个物体"用 `mentions`（含地图里没有的），  
判定"能不能回答"用 `matched_labels`（地图里真实存在的）。  
分开是必要的——否则"杯子在哪"（地图里没有杯子）会被误判成"描述场景"，  
而正确行为是回答"没找到杯子"。

### 4.5 开放词汇查询评测（`scripts/16_eval_openvocab_query.py`）

**为什么要拆两个维度测。** "开放词汇"直觉上像"查询没见过的类别"，但直接这么测会得到平凡失败：  
地图物体来自检测器，**没被检测到的类别压根不在地图里**，查询必然落空 ——  
那测的是检测器的类别覆盖，不是查询接口的泛化能力。所以拆成：

- **未见表达命中率**：用**没在 prompts 里出现过**的说法指代**已建图**的物体；
- **未见类别拒识率**：查询**地图里没有**的类别时应返回空。

只看命中率会高估（永远返回"最像的东西"也有不错的命中率，但会指向错误位置）；  
只看拒识率会低估（什么都不返回自然 100% 拒识）。综合分 = **命中率 × 拒识率**。

命中率还必须**再按表达类型拆开**，否则同样会高估：别名表能覆盖"中文名/近义词"（命名类），  
但对"a thing to drink from"这类**描述性短语必然失败** —— 后者才是开放词汇的试金石。

**规模**：6 个合成场景 / 151 条未见表达（命名 111 + 描述 40）/ 72 条未见类别查询。

| 查询路径              | 命名类命中      | 描述类命中     | 拒识率        | 综合分       |
| ----------------- | ---------- | --------- | ---------- | --------- |
| 纯词法（别名表）          | **100.0%** | 35.0%     | **100.0%** | 0.828     |
| 纯嵌入（SigLIP）       | 31.5%      | 12.5%     | 87.5%      | 0.232     |
| **融合 hybrid（默认）** | **100.0%** | **37.5%** | **100.0%** | **0.834** |

**结论与一条实测出来的缺陷。** 初版默认词法阈值是 0.05，综合分只有 0.603 ——  
拒识率仅 72.2%，即**近三成的"地图里没有的类别"查询会返回一个错误物体**。  
根因是打分分层：概念命中 1.00 / 子串 0.85 / 字符 bigram Jaccard 上限 0.80，  
第三层是纯噪声（`bicycle` 与 `bottle` 共享 bigram `le`，Jaccard 0.09 → 0.145 分）。  
阈值抬到 0.5 后拒识率 100%、命名类命中率不降，综合分 0.603 → **0.828**；  
且扫描出的最优阈值恰好就是引擎默认值。已加回归测试锁定  
（`test_lexical_threshold_rejects_ngram_noise`）。

**嵌入侧的阈值必须就地标定，且要区分它在流水线中的角色。** SigLIP 声明的  
`suggested_pair_threshold = 0.02` 是在**检测区域特征**上量的，而查询比对的是  
**多视角融合后的地图物体特征**，后者分数尺度小约 20 倍。实测阈值曲线（纯嵌入路径）：

| 嵌入阈值             | 命名类   | 描述类   | 拒识率    | 综合分       |
| ---------------- | ----- | ----- | ------ | --------- |
| 5e-05            | 41.4% | 20.0% | 59.7%  | 0.214     |
| **5e-04（纯嵌入最优）** | 31.5% | 12.5% | 87.5%  | **0.232** |
| 0.001            | 27.9% | 10.0% | 91.7%  | 0.212     |
| 0.02（hybrid 最优）  | 3.6%  | 2.5%  | 100.0% | 0.033     |

同一个阈值在 hybrid 下最优、在纯嵌入下几乎全拒空 —— 因为**角色不同**：  
hybrid 里词法已负责接受判定，嵌入阈值退化为**精度过滤器**（收紧不损失命中、  
却减少假接受）；纯嵌入里它就是唯一的**接受阈值**（收紧直接砍召回）。  
两者最优值差 **40 倍**。现在由 `Encoder.suggested_pair_threshold` 与  
`Encoder.suggested_standalone_threshold` 分别承载，`QueryEngine` 按自身模式自动选择  
（地图上显式设了 `query_min_score_embedding` 时以用户为准）。

**一条关于评测本身的教训（比数字更重要）。** 本节的嵌入数字在第一版评测里是虚高的：  
评测脚本在**纯嵌入模式**下排序时误从样本里读了词法分数，于是量出来的"纯嵌入"  
混进了词法信号，报成命名类 78.4% / 描述类 25.0%。把排序视图改成与当前模式一致后，  
真实值是 **31.5% / 12.5%**。**评测脚本必须和被测路径共用同一套视图，  
否则量的是别的东西 —— 而且错的方向总是"看起来更好"。**

**阈值自标定：把"人工扫描"换成"自监督"（4.5 缺陷的根治）。**  
前面所有阈值都是离线扫出来的常量，换数据集/换编码器就得重扫。但地图建好后，  
每个物体都带着检测器给的标签 —— **这本身就是一份标定集**：  
物体对自己的标签应得高分、对别的标签应得低分。据此选阈值即可，无需任何 GT。

选点准则用**最大化平衡准确率** `TPR + TNR`（不用准确率：正样本 N 个、  
负样本是它的 U−1 倍，极不平衡）；并列最优时取**更大的**阈值（同样是满分宁可严一点）。

| 纯嵌入方案          | 命名类       | 描述类   | 拒识率   | 综合分       |
| -------------- | --------- | ----- | ----- | --------- |
| 硬编码常量 0.0005   | 31.5%     | 12.5% | 87.5% | 0.232     |
| **自监督标定（逐场景）** | **41.4%** | 12.5% | 86.1% | **0.291** |

标定阈值范围 7.2e-05 ~ 2.4e-03（每场景自适应）。**自监督标定优于硬编码常量**  
（综合分 +0.059），于是硬编码值降级为"标定不可行时的回退"（物体 <2 个、  
只有一个类别、编码器异常）。

⚠️ **标定必须走查询时完全相同的那条打分路径**（同一个 `EmbeddingMatcher.score`）。  
若用底层 `pair_scores` 直接标、却用 matcher 校准后的分数查询，两者不在同一尺度上 ——  
这与上一条"评测视图"是**同一类错误**：**只要有两处独立实现同一个打分逻辑，  
就一定会漂移。**

**否定实验：自监督标定不能无脑推广到词法路径。**  
很自然的下一个想法是"同一套 (标签, 标签) 打分，词法阈值也该能自标定"。  
实测**会变差**：

| 路径 | 标定集分离度 (BA，上界 2.0)     | 标定阈值            | 综合分                 |
| -- | ---------------------- | --------------- | ------------------- |
| 词法 | **2.000**（正负样本完全可分）    | 0.90 ~ 0.95     | 0.828 → **0.742** ↓ |
| 嵌入 | **1.33 ~ 1.50**（有明显重叠） | 7e-05 ~ 2.4e-03 | 0.232 → **0.291** ↑ |

根因是**标定集与部署分布不匹配**：词法标定集是"标签查自己"，  
别名表对自身必然命中 1.0、对别的≈0，正负样本**完全可分**，  
于是优化器把阈值推到正样本分布的最边缘（≈0.90）——  
而真实查询（"杯子"、"seat"）常只落在**子串那层（0.85）**，全被误杀。  
嵌入标定集的分布本就重叠，阈值落在有意义的间隙里，所以泛化得好。

**可推广的判据：自监督标定只在「标定集难度 ≈ 部署难度」时才有效；  
标定集比真实场景简单 → 阈值必然过严。**  
而**平衡准确率接近上界 2.0，正是"标定集太简单"的直接证据 ——  
在标定集上看着像满分，实际是危险信号。**

**诚实的边界。** 本基准只有 10 个类别且全部在别名表内，对词法路径**天然有利**；  
融合相比纯词法在描述类上只多命中 1/40 条（37.5% vs 35.0%），边际贡献很小。  
嵌入路径的真正价值要等词汇量超出别名表覆盖、或需要处理任意自然语言描述时才会显现 ——  
这也是"词法保底 + 嵌入扩展"分层设计的理由，而不是用嵌入直接替换词法。


### 4.6 区域语义与 VLM 空间问答

这一节直接对应岗位要求里的"视觉语言模型算法"。

**区域语义（`scripts/13_benchmark_region_semantics.py`）。** 用 SigLIP + 多裁剪 TTA  
对区域做开放词汇分类，分离"检测"与"编码"两个环节的贡献：

| 输入区域                    | Top-1    | Top-3    | MRR       |
| ----------------------- | -------- | -------- | --------- |
| 检测器输出的区域                | 0.54     | —        | —         |
| **GT 框 + GT 标签**（编码器上限） | **0.76** | **1.00** | **0.878** |

差距说明**瓶颈在检测、不在编码器** —— 编码器在有干净区域时几乎总能排对，  
所以优化预算应该投到检测/掩码，而不是换更大的视觉塔。

**VLM 空间问答（`scripts/12–14`）。** Qwen2-VL-2B + LoRA（4bit 量化，1359 样本，  
2 epoch / 338 step / 2954 s，显存峰值 3.684 GB，可训练 9.23M 参数占 0.42%，  
冻结视觉塔与 merger）：

| 指标       | 微调前     | 微调后                   |
| -------- | ------- | --------------------- |
| 输出格式可解析率 | 8.3%    | **100.0%**            |
| 单位正确率    | 4.2%    | **100.0%**            |
| 空间关系准确率  | 0%      | **100.0%**            |
| 距离 MAE   | —       | 0.420 m（41.7% ≤0.3 m） |
| 3D 坐标误差  | 2.756 m | **1.346 m**           |

**务必读懂这张表的边界。** 前四项是**格式与语义**能力，微调把"会不会按格式说话"  
从 8.3% 拉到 100%，这是 LoRA 最可靠的价值。但最后一行暴露了本质：  
**1.346 m 的坐标误差说明单目 RGB 恢复不出绝对尺度** —— 这不是微调不够，  
而是任务本身病态。所以本项目的架构结论是：  
**几何走投影（毫米级）、语义走 VLM（任意表达）**，而不是让 VLM 直接输出 3D 坐标。  
这个结论比"VLM 提升了多少"更有工程价值。

**加入规则引擎基线后，上述结论从经验判断变成定量证据。**  
`scripts/14_eval_vlm_spatial.py --rule-baseline` 用规则引擎在**精确 3D 地图**上回答  
同一批问题，给出几何能达到的上界。注意这是 **oracle 上界**（GT 答案本来就是这套  
规则引擎生成的，满分是预期结果）—— 它的作用是当**天花板**用于**归因**，  
而不是当"对手"：

| 任务   | 指标          | 基座          | 微调后             | **规则引擎（上界）**    |
| ---- | ----------- | ----------- | --------------- | --------------- |
| 米制距离 | 距离 MAE      | 不可解析        | 0.420 m         | **0.000 m**     |
| 米制距离 | ≤0.3m 比例    | 0%          | 41.7%           | **100%**        |
| 物体定位 | 3D 坐标误差     | 2.756 m     | 1.346 m         | **0.000 m**     |
| 相对关系 | 准确率         | 不可解析        | **100%**        | **100%**        |
| 全局   | 可解析率 / 含单位率 | 8.3% / 4.2% | **100% / 100%** | **100% / 100%** |

**读法**：微调后的 VLM 在**语义与格式维度完全追平几何上界**  
（关系准确率、可解析率、单位率都是 100%），但在**度量维度差 1~2 个数量级**。  
于是分工可以精确表述为：**VLM 负责意图解析、指代消解与结构化输出；  
米制数值必须来自几何。** 两者通过结构化输出对接（`reasoning/vlm.py` 的  
`HybridReasoner` 就是这么做的）。

⚠️ **实现这个基线时的教训**：第一版按**问题文本**匹配答案，结果一个本该满分的  
oracle 基线跑出"距离 MAE 0.178 m、坐标误差 1.001 m"。根因是**同一句话会在多个  
合成场景里重复出现而答案不同** —— 键冲突导致匹配到了别的场景的答案。  
改用 **(图像, 问题)** 做键后匹配率 100%、指标归零。  
**一个"上界"没拿到满分时，先怀疑自己的评测接线，而不是急着解释结果。**

## 五、设计取舍总结

| 决策点         | 选择                   | 理由                                                     | 代价                     |
| ----------- | -------------------- | ------------------------------------------------------ | ---------------------- |
| 物体构建        | 实例关联                 | 空间聚类会合并相邻物体                                            | 需要实例信息（可降级到聚类）         |
| 3D 表示       | 体素特征场                | 多视角融合 + 整数键 + 抗噪                                       | 内存随分辨率立方增长             |
| 开放词汇载体      | 特征向量                 | 任意文本可比                                                 | 需要 CLIP 才有文本侧          |
| **VLM 的角色** | **只做语义，不做几何**        | 单目 RGB 恢复不出绝对尺度（实测坐标误差 1.35 m）                         | 两套模块需协同                |
| **查询阈值**    | **自监督标定**（回退到编码器声明值） | 用地图自身的 (特征, 标签) 对定阈值：无需 GT、逐场景自适应、换数据集不用重扫；实测优于人工扫描的常量 | 需要地图已有 ≥2 个类别；词法路径尚未接入 |
| 推理          | 规则保底 + VLM 增强        | 保精度 + 保灵活                                              | 两套代码要维护                |
| 部署          | 快慢分级                 | 慢任务不阻塞实时链路                                             | 受 GIL 限制，非真并行          |
| 降级实现        | 每个后端都配               | CI 可跑 + 错误可二分                                          | 需要诚实标注降级代价             |

## 六、局限与后续工作

**已知局限**（详见 README"已知局限"）：

1. 离线 stub 检测器依赖 GT 框；
2. bbox 当掩码使 3D 框偏大（已量化，见 4.4；换 SAM 后误差从 1.324 m 降到 0.555 m）；
3. 虚拟相机重渲染有遮挡空洞；
4. **词法匹配不是真开放词汇** —— 且实测发现别名表在本基准上"太强"，  
   掩盖了嵌入路径的真实价值（见 4.5 的诚实边界）；
5. 异步流水线受 GIL 限制；
6. ~~ROS2 **未上真机**~~ —— 已在**两条独立路径**上跑通：  
   RoboStack Windows（里程计位姿）与 **WSL2 + Ubuntu 22.04 + ROS2 Humble  
   （`tf2_ros` 真实 TF 树）**，都是 6 帧 / 0 位姿失败 / 物体误差 0.053~0.534 m，  
   且两者**逐位一致** —— 两套独立位姿来源产出相同地图，是对 TF 约定处理的强交叉验证。  
   过程中真实 rclpy 抓出 **4 个**离线测试覆盖不到的 bug  
   （含一个根因级的：`stamp` 是 float 而 tf2 要 `Time`，异常被 identity 兜底吞掉，  
   表现为"6 帧却 0 体素、`pose_failures` 仍为 0"）。**仍未覆盖**：真机硬件联调。
7. **VLM 不能输出度量几何** —— 单目 RGB 恢复不出绝对尺度，实测 3D 坐标误差 1.35 m，  
   所以几何走投影、语义走 VLM（见"设计取舍"）；
8. **VLM 评测集偏小**，绝对数值应看作趋势而非稳定指标。

   词法标定集正负样本完全可分（BA = 2.0），阈值被推到 ≈0.90，
