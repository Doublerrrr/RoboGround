### 模型下载：Windows 符号链接坑

**现象**：`snapshot_download('openai/clip-vit-base-patch32')` 报
`OSError: [WinError 1314] 客户端没有所需的特权`。

**根因**：HuggingFace Hub 默认在 cache 里用**符号链接**把 snapshots 指向 blobs，
Windows 上创建符号链接需要开发者模式或管理员权限。

**解法**：改用 `local_dir` 参数（直接下载到目标目录，不走 symlink）：

```python
snapshot_download('openai/clip-vit-base-patch32',
                  local_dir=r'G:\RoboGround\weights\clip-vit-base-patch32')
```

**已下载的权重**：

| 模型 | 大小 | 路径 |
|---|---|---|
| Grounding DINO tiny | 690 MB | `weights/hf/hub/models--IDEA-Research--grounding-dino-tiny` |
| SAM vit-base | 375 MB | `weights/hf/hub/models--facebook--sam-vit-base` |
| DINOv2 small | 88 MB | `weights/hf/hub/models--facebook--dinov2-small` |
| CLIP ViT-B/32 | 1820 MB | `weights/clip-vit-base-patch32/`（local_dir） |
| SigLIP base-patch16-224 | 1629 MB | `weights/siglip-base-patch16-224/`（local_dir） |

**网络**：HuggingFace 直连超时；本机 Clash 代理 `127.0.0.1:7897` 可用。
下载时设置 `HTTPS_PROXY=http://127.0.0.1:7897`。

## 三、★ 修复的 6 个真实集成问题

### 问题 1：Grounding DINO 的标签是"原始文本片段"

**现象**：检出标签出现 `'trash'`（prompt 写的是 `'trash can'`）、
甚至 `'table bookshelf'`（跨 prompt 的合并片段）。

**影响**：地图标签不统一 → 词法匹配失效 → 查询"垃圾桶"命中不了。

**解法**：加 `canonicalize_labels`（默认开），把检出标签**映射回最匹配的 prompt**，
并丢弃与任何 prompt 都不匹配的"幻觉类别"（`min_label_match=0.5`）。

**效果**：`trash` → `trash can` ✓，`table bookshelf` → `table` ✓。

### 问题 2：首次推理含 CUDA 初始化，延迟虚高 4 倍

**现象**：480×640 图上首次 `detect` 耗时 **1376 ms**。

**根因**：第一次调用包含 CUDA context 建立 + cuDNN autotune。

**解法**：`warmup()` 里跑一次 64×64 的哑推理。

**效果**：**1376 ms → 351 ms**（3.9× 提速）。做延迟基准前必须 warmup，否则数字没意义。

### 问题 3：`labels` 键即将废弃（前向兼容）

transformers ≥4.51 起 `post_process_grounded_object_detection` 的 `labels`
会返回**整数 id**，字符串名要取 `text_labels`。
代码已改为优先 `text_labels`，避免升级后静默拿错标签。

### 问题 4：★ 嵌入分数没有拒识能力（最严重）

**现象**：查"冰箱"（地图里确定没有）返回了 chair，score=0.559。
查"微波炉"返回 monitor，score=0.873。

**根因**：原始余弦相似度只在 0.1~0.3 窄区间波动，把它线性映射到 `[0,1]`
（`(sim+1)/2`）之后，**任何 query 对任何物体都得到 ~0.55 分**，
阈值完全失去意义。对机器人来说这是危险行为 —— 它会据此去一个完全错误的位置。

**解法**：三层修复
1. **空文本校准**：把 query 相似度与一组空文本
   （"a photo of nothing" / "an empty background" ...）的相似度放进同一 softmax，
   取 query 那一项的概率。不匹配的候选会掉到接近 0。
2. **双阈值接受**：词法（命中即 1.0，阈值见下方 ⚠️ 修正）与嵌入
   （概率语义，阈值 0.9）用**各自**的阈值，任一路径达标即接受。
   > ⚠️ **修正（2026-09-11）**：当时给词法定的阈值是 **0.05，太低了**。
   > 词法的第三层打分是字符 bigram Jaccard（上限 0.80），属于纯噪声
   > （`bicycle` 与 `bottle` 共享 `le` → 0.145 分），0.05 会把它们全放行。
   > 实测 72 条"未见类别"查询里 **27.8% 返回了错误物体**。
   > 现值 **0.5**（拒识率 72.2% → 100%，命名类命中率不降）。
   > 详见 `docs/实现笔记.md` 第 2.2b 节与 `scripts/16_eval_openvocab_query.py`。
3. **温度标定**：τ=0.01 太锐利（任何正 margin 都趋近 1.0，实测"桌子"误命中 0.971），
   用 `scripts/10_calibrate_embedding.py` 扫描后选 **τ=0.02**。

**效果**：`冰箱` → **无命中** ✓，`微波炉` 由 0.873 降到 0.556。

### 问题 5：CLIP 是纯英文模型，中文查询等于喂噪声

**现象**：查询"杯子"时嵌入路径给出的结果完全随机。

**根因**：`openai/clip-vit-base-patch32` 的文本塔只训过英文。

**解法**：**用双语别名表做中文→英文概念桥接**：
"杯子" → `cup` → 套 CLIP 模板 `"a photo of a cup."`。
但桥接必须**保守**（只对含中文或 ≤2 个词的短文本做），
否则 `"something to drink from the table"` 会被子串匹配错误地变成 `"table"`（实测踩过）。

### 问题 6：测试脚本截断了检测列表（我自己的 bug）

**现象**：10 个检测只有 3 个进了地图。

**根因**：`step_segment` 用 `dets = r.pop("detections", dets)` 把检测列表
替换成了"只送进 SAM 的子集"，导致没轮到 SAM 的 7 个检测被整个丢掉。

**修法**：SAM 只对前 `max_boxes` 个框做精细分割（其余保持原掩码），
但**返回完整列表**；调用方绝不能截断。
修好后观测数 **3 → 7**。

**教训**：这类"优化路径截断数据"的 bug 不会报错，只会让结果静默变少 ——
所以给 MapBuilder 加了 `drop_stats` 统计（见问题 7）。

### 问题 7：静默丢弃数据（可观测性缺失）

反投影失败的检测原来被**静默丢弃**。实测在真实 SUN RGB-D 上常有一半检测
因为"掩码区域内无有效深度"（门窗/玻璃/太远/太近）而无法反投影。

**修法**：MapBuilder 增加 `drop_stats`，finalize 时打印：
```
数据流统计：10 个检测 → 丢弃 3 个（掩码区域无有效深度，常见于门窗/玻璃/过远）、0 个（低置信度）
```

**意义**：否则使用者会误以为"检测器没检出"，而归因完全错。

## 四、★ 消融实验：编码器 × 池化（最重要的结论）

### 实验设置

- 数据：真实 SUN RGB-D 2 个场景（场景 1236 / 1251），共 **35 个有效检测样本**
- 流程：Grounding DINO 检测 → SAM 精细掩码 → 区域裁剪 → 编码 → 与类别文本比对
- 指标：`self_sim`（与自身标签文本的相似度）、`other_sim`（与其他类别的最大相似度）、
  `分离度 = self_sim - other_sim`（**>0 才算方向正确**）、`Top1`、`中位排名`
- 脚本：`python scripts/11_ablate_clip_pooling.py`

### 结果

| 编码器 | 池化 | 校准方式 | self_sim | other_sim | 分离度 | **Top-1** | 中位排名 |
|---|---|---|---|---|---|---|---|
| CLIP B/32 | crop | 余弦（需校准） | 0.252 | 0.255 | **−0.003** | 0.43 | 2.0 |
| CLIP B/32 | mask | 余弦（需校准） | 0.233 | 0.241 | **−0.009** | 0.20 | 3.0 |
| SigLIP base | crop | **原生 sigmoid** | 0.037 | 0.034 | +0.002 | 0.49 | 2.0 |
| **SigLIP base** | **mask** | **原生 sigmoid** | 0.004 | 0.002 | **+0.003** | **0.54** | **1.0** |

### 三条结论

1. **CLIP ViT-B/32 的区域特征在这里是"负分离度"** ——
   即"和别的类别反而更像"，基本无法区分室内家具类别。
   它的余弦分数区间只有 0.23~0.26，几乎全部挤在一起。
2. **SigLIP 明显更好**：Top-1 **0.43 → 0.54**（+11 绝对百分点），
   中位排名 **2.0 → 1.0**（意味着至少一半样本自身标签排第一），
   分离度**首次转正**。原因是 sigmoid 损失给每个图文对独立概率，
   而 CLIP 的 softmax 是对比式的"相对谁更像"。
3. **方形填充是有效的廉价改进**：CLIP 从 Top-1 0.34（无填充、context=0.05）
   提升到 0.43（方形填充、context=0.15）。原因是非方形裁剪被 resize 成
   224×224 时会**拉伸变形**，变形后的"书架"和"桌子"在模型眼里差不多。

### 诚实评价

**Top-1 = 0.54 仍然不高**（4~6 类，随机约 0.20）。
这说明"用单张区域裁剪 + 单塔图文模型做细粒度家具分类"本身是有上限的。
可行的改进方向：

1. **多尺度裁剪 + 更强上下文**（当前只用了单一裁剪）；
2. **用 DINOv2 的密集特征做区域池化**（patch 级特征比整块编码更精确）；
3. **主要依赖检测器的文本对齐头**：Grounding DINO 本身就是开放词汇检测器，
   它的文本-区域对齐比"事后用另一个模型编码裁剪"更准。
   本项目现在就是这么做的（`canonicalize_labels` 把检出标签映射回 prompt），
   嵌入匹配作为**补充**而非主力。
4. 换更大的模型（CLIP-L/14、SigLIP-so400m）—— 但 8GB 显存下要权衡。

**这个结论本身很有价值**：它说明"开放词汇"不是装个 CLIP 就完事，
区域级对齐的质量取决于模型选择与特征提取方式，必须用数据验证。

## 五、SigLIP 的阈值必须按编码器自适应（否则全空）

**现象**：把 CLIP 标定出的阈值 0.5 用到 SigLIP 上，**所有查询返回空**。

**根因**：SigLIP 的 sigmoid 概率**天然保守** ——
`logit_bias = -12.93` 把整体压得很低，即使是**正确类别**的图文对，
概率也只有 0.01~0.05 量级（实测命中样本 0.037）。

**解法**：让编码器**自己声明**建议阈值：

```python
Encoder.suggested_pair_threshold       # 默认 0.5
SigLIPEncoder.suggested_pair_threshold # 0.02（实测）
```

`QueryEngine` 读取它；config 里 `query.min_score_embedding: null` 表示自适应。

**通用教训**：**不同模型的分数尺度可以差两个数量级，
任何"全局阈值"都是错的。** 阈值必须跟着分数定义走。

## 六、SAM vs bbox：反投影精度的量化

| 指标 | bbox 掩码 | SAM 掩码 | 说明 |
|---|---|---|---|
| 掩码平均像素数 | 6894 | 2893 | — |
| SAM/bbox 比 | — | **0.51** | SAM 剔除了 **48.8%** 的背景像素 |
| 处理耗时 | ~0 | 73 ms/框（6 框 437 ms） | SAM 的 prompt encoder + mask decoder 是逐框的 |

**这正是"该用 SAM 而不是 bbox"的量化证据**：
bbox 反投影会把框内的地面/墙点也纳入 3D 包围盒，导致预测框显著偏大、IoU ≈ 0。

**代价**：SAM 逐框约 73 ms。32 个框就是 2.3 秒 —— 端侧实时链路里
必须限制 `max_boxes`，或者把 SAM 放到慢档、快档只用 bbox。

## 七、单场景端到端结果

场景 #1236（SUN RGB-D，640×480）：

```
Grounding DINO 检出 10 个目标（351 ms）
  ↓ 标签规范化
  ['bookshelf', 'chair', 'cup', 'door', 'monitor', 'trash can']
  ↓ SAM 精细掩码（6 框 437 ms，剔除 48.8% 背景）
  ↓ 反投影（丢弃 3 个：掩码区域无有效深度 —— door/cup/bookshelf）
7 个观测 → 4 条物体轨迹 → 1805 体素 → 4 个物体
```

**查询结果（混合模式，词法 + SigLIP 嵌入）**：

| 查询 | 结果 | 分数 | 评价 |
|---|---|---|---|
| `椅子` | chair | 0.963 | ✓ |
| `显示器` | monitor | 0.880 | ✓ |
| `杯子` | 无命中 | — | ✓ 地图里确实没有杯子 |
| `桌子` | 无命中 | — | ✓ 该场景地图里没有 table |
| `冰箱` | 无命中 | — | ✓ **拒识正确**（之前会误返回 chair） |
| `something to drink from` | monitor | 0.064 | ⚠️ 弱误命中（阈值 0.02，此处 3 倍） |

**唯一剩下的问题**是"从未出现过的自由表达"仍可能弱误命中。
考虑到 SigLIP 概率的保守性（命中仅 0.037~0.074），
把阈值提到 0.07 能滤掉它，但会误杀弱命中 —— 这需要在更多场景上做标定
（`scripts/10_calibrate_embedding.py` 已提供工具）。
