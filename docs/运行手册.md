## 一、环境安装

### 1.1 前置检查

```bash
python scripts/01_check_env.py
```

**预期**：核心依赖全 ✓，torch 2.5.1 cuda=True，GPU 显示 RTX 4060。

**如果报错**：
| 现象 | 原因 | 解决 |
|---|---|---|
| `No module named 'torch'` | 用了 base 环境（Python 3.14） | `conda activate lxr` |
| `torch.cuda.is_available() == False` | torch 被 pip 覆盖成 CPU 版 | 重装 cu124：见 `setup_env.md` |
| `缺少 numpy/scipy/yaml` | 没装本项目 | `pip install -e .` |

### 1.2 安装

```bash

cd G:\RoboGround

pip install -e .              # 核心（大部分 lxr 已自带）
pip install -e ".[dev]"       # 开发（pytest）
```

### 1.3 可选依赖（按需，不装也能跑）

```bash

pip install -e ".[vlm]"          # Qwen2-VL + LoRA
pip install -e ".[export]"       # onnx / onnxruntime
```

## 三、用真实数据（SUN RGB-D）

### 3.1 建索引（一次性，约 30 秒）

```bash
python scripts/02_build_sunrgbd_index.py
```

**前提**：`G:\sunrgbd_raw\` 下有 `SUNRGBD/` 与 `SUNRGBDtoolbox/`。

**预期**：
```
[+] 索引已保存：G:\RoboGround\data\cache\sunrgbd_index.npz（10335 个有效场景，跳过 0 个）
[*] 索引概况
      场景数        : 10335
      GT 框总数     : 64783
      构建耗时(s)   : 30.2
```

**如果报错**：
| 现象 | 解决 |
|---|---|
| `找不到 SUN RGB-D 元数据` | 用 `--root` / `--meta` 指定正确路径 |
| 场景数很少（如 <100） | 加了 `--limit`；或不加 `--no-verify-files` 时文件缺失 |

### 3.2 建图

```bash
# 自动挑一个物体多、类别丰富的场景
python scripts/03_build_map.py --source sunrgbd --resize 400 --save runs/map_sunrgbd.npz

# 指定场景 + 指定 prompts（开放词汇：换 prompt 就换"要找什么"）
python scripts/03_build_map.py --source sunrgbd --scene 1236 \
    --prompts chair table monitor desk --save runs/map_s2.npz
```

**预期输出**：物体清单（每行一个物体：标签、中心、尺寸、置信度、体素数）+ 与 GT 的定位对比。

### 3.3 真实多视角全景融合（可选，需要 2D-3D-S）

**先说清楚"多视角"从哪来**：SUN RGB-D **每个场景只有一张** RGB-D 图，
所以多视角不可能来自它。旧做法是把这一张图反投影成点云、再用**虚拟相机重渲染**出
N 个视角 —— 那是同一份观测的重采样，**不增加信息**（实测无效深度像素 42.8% → 77.0%），
这条链路（`virtual_camera.py` + 脚本 26/27）**已经删除**，只作为历史记录留在
`docs/多视角数据核查报告.md`。

现在的多视角走 **Stanford 2D-3D-S**：同一采集点上有 **N 个真实拍摄的视角**
（绕竖直轴的水平环），融合成**一张 360° 等距柱状全景**：

```bash
# 前提：数据在 G:\2d3ds\area_1\area_1（约 13.8 GB；脚本的 --root 默认值就是它）

# ① 数据集级统计：覆盖率随视角数单调上升 / 光轴仰角分布 / 光心离散度
python scripts/36_pano_dataset_stats.py

# ② ★ 融合出的全景 vs 官方全景逐像素比对（深度 MAE、比值中位）
python scripts/35_validate_pano_vs_official.py --all --n 3

# ③ ★ 全景 → RGBDFrame → 建图 / 查询，并做等距柱状 vs 针孔反投影消融
python scripts/37_eval_pano_grounding.py --rooms office_6 hallway_6 office_27
```

**产物**：`runs/36_pano_dataset_stats.json`、`runs/35_validate_pano_vs_official.log`、
`runs/37_eval_pano_grounding.json`。判据都写在产物里，不用信文档转述。

**两条要注意**：

1. **这三个脚本不在默认测试套件里** —— `pytest` 不依赖 2D-3D-S，没下数据也能全绿；
   没下数据时它们会直接报找不到 `--root`。
2. **融合出的全景只是水平环带**（垂直约 ±55°）：3,345 个真实视角的光轴仰角
   全落在 −22.9° ~ +23.7°，**天顶/天底从未被观测**；
   它也**还没有**产出与单帧同口径的定位误差对比。详见 `docs/多视角全景融合报告.md`。

### 3.4 查询与推理

```bash
# 手动提问
python scripts/04_query_demo.py runs/map_sunrgbd.npz "桌子在哪" "椅子离桌子多远"

# 自动生成一批问题
python scripts/04_query_demo.py runs/map_sunrgbd.npz --auto

# 打印全部空间关系
python scripts/04_query_demo.py runs/map_sunrgbd.npz --relations --relations-radius 3
```

**支持的问法**：

| 意图 | 例子 |
|---|---|
| 定位 | `杯子在哪` / `where is the cup` |
| 测距 | `杯子离桌子多远` / `椅子到门有多远` |
| 关系判断 | `杯子在桌子上面吗` |
| 区域列举 | `桌子上有什么` |
| 最近邻 | `离我最近的门` |
| 计数 | `有几个椅子` |
| 场景描述 | `描述一下场景` |
| 未找到 | `冰箱在哪`（地图里没有 → 明确回答"没找到"） |

## 四、评测与出数字

### 4.1 基准测试

```bash
# 合成场景（最快）
python scripts/05_benchmark.py --source synthetic --frames 5 --out runs/bench_syn.json

# 真实数据多场景
python scripts/05_benchmark.py --source sunrgbd --scenes 10 --out runs/bench_real.json

# 真实多视角全景场景上的下游链路 + 反投影消融（2D-3D-S，见 §3.3）
python scripts/37_eval_pano_grounding.py --rooms office_6 hallway_6 office_27

# 附带给量化对照实验
python scripts/05_benchmark.py --source synthetic --quantization
```

**产出**：`--out X.json` 会同时写出两份 —— `X.json`（原始数据）与 `X.md`（可读报告）。
例如上面第一条命令产出 `runs/bench_syn.json` + `runs/bench_syn.md`
（**实测确认**：`scripts/05_benchmark.py` 打印「报告已保存：…」时会同时给出这两个路径）。

> ⚠️ 这里以前写的是 `runs/benchmark.json` / `runs/benchmark.md`，但命令里的
> `--out` 并不是这个名字，两者对不上；而且 `runs/benchmark.*` 在本机**并不存在**。
> 已改成按 `--out` 描述。查历史数字时注意：`runs/b2.md` 是合成基准的真实产物
> （median 0.2180 m、≤0.25 m 100%），`runs/bench_sunrgbd.json` 是真实单帧基准
> （median 0.38098 m、≤0.25 m 3.8%）。

**报告结构**：
- 规模与总耗时
- 阶段耗时（perceive / query）
- **地图级定位精度**（主要质量指标）
- 观测级定位精度
- 检测指标（bbox 基线，附带为什么低）
- 查询命中率

### 4.2 当前实测数字（供对照）

| 场景 | 地图级中位误差 | ≤0.25m |
|---|---|---|
| 合成 4 视角 | **0.218 m** | 100% |
| 真实单帧 | **0.381 m** | 3.8% |
| 6 个**渲染**视角（非真实多视角） | **0.259 m** | 45.7% |

> ★ 第三行出自**已删除**的虚拟视角链路（`--source virtual` / 脚本 26、27）：

## 五、自动化标注（Stage 5）

```bash
# 合成数据
python scripts/06_auto_label.py --source synthetic --frames 6 --out runs/labels

# 真实数据 + 跨帧一致性检查
python scripts/06_auto_label.py --source sunrgbd --scenes 10 \
    --out runs/labels --check-consistency

# 调闸门阈值
python scripts/06_auto_label.py --source synthetic \
    --min-score 0.5 --min-points 50 --no-scale-check
```

**产出三份文件**：
| 文件 | 用途 |
|---|---|
| `coco.json` | 2D 检测/分割标注（喂 YOLO/Mask2Former） |
| `boxes3d.json` | 3D 框标注（喂 3D 检测 / VLM 空间推理） |
| `review.json` | 被闸门拦下、需人工复核（**不是丢弃**，这才是主动学习的价值） |
| `consistency_suspects.json` | 跨帧不一致的可疑标注（加 `--check-consistency` 时） |

**四道质量闸门**：置信度 / 几何有效性（点数）/ 尺度合理性（物理先验）/ 跨帧一致性

**尺度先验表**在 `src/roboground/data/auto_label.py` 的 `PLAUSIBLE_SIZE_RANGES`，
可以直接改（例如加新类别）。

### 6.3 异步快慢分级流水线

```python
from roboground.deployment import AsyncPipeline
from roboground.mapping import MapBuilder
from roboground.reasoning import RuleEngine

builder = MapBuilder(cfg)
engine_holder = {}

def fast(frame):                      # 高频：感知 + 建图
    builder.add_frame(frame)
    return builder.finalize()

def slow():                           # 低频：推理
    smap = pipe.get_snapshot()
    if smap is None:
        return None
    engine = engine_holder.setdefault("engine", RuleEngine(smap, cfg=cfg))
    return engine.answer("描述一下场景")

pipe = AsyncPipeline(fast, slow, fast_hz=10.0, slow_hz=1.0, queue_size=4)
pipe.start()
for frame in video_stream:
    pipe.submit(frame)               # 队列满会丢最旧帧，绝不阻塞
print(pipe.describe())
pipe.stop()
```

### 6.4 ROS2（可选）

前提：安装 ROS2 Humble（**不要用 pip**，用官方安装包）。

**推荐路径：标准 ament 包**（参数可在线调、launch 一把起、TF 树可选）：

```bash
# 一次性构建

source install/setup.bash

# 起全链路（感知 + 问答）；无真机时加 static_tf:=true 一起发完整 TF 树
ros2 launch roboground_ros full.launch.py static_tf:=true

# 提问 / 看答案 / 看地图
ros2 topic pub --once /roboground/query std_msgs/String "{data: '杯子在哪'}"
ros2 topic echo /roboground/answer
ros2 topic echo /roboground/semantic_map

# 在线调参（热参数下一帧生效）
```

```bash
# 终端 2：问答节点
```

## 八、故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `No module named torch` | 用了 base 环境 | `conda activate lxr` |
| `torch.cuda.is_available()==False` | torch 被覆盖 | 重装 cu124 |
| 深度图全 0 | 用 cv2 读了 16 位 PNG | 本项目已用 PIL，检查数据路径 |
| 点云尺度差 10 倍 | `depth_scale` 写错 | SUN RGB-D 应为 10000 |
| 查询返回空 | 物体不在 prompts 覆盖范围内 | 加 `--prompts` 或改 config |
| 物体被合并 | 用了 `object_mode: clustering` | 改回 `association` |
| 检测 IoU ≈ 0 | bbox 当掩码（预期） | 换 SAM，或看 `map_localization` |
| 中文控制台乱码 | GBK 编码 | 已自动重配 UTF-8；仍乱码设 `PYTHONIOENCODING=utf-8` |
| 测试报 `No module named pytest` | 没装 dev 依赖 | `pip install -e ".[dev]"` |
| DataLoader 卡死 | `num_workers > 0` | 本机沙箱必须为 0 |

## 九、性能调优

| 目标 | 手段 |
|---|---|
| 建图更快 | 增大 `geometry.voxel_size`；降 `--resize`；`segmenter: box` 而非 `sam` |
| 内存更省 | 降 `mapping.max_voxels`；降 `geometry.max_points_per_frame` |
| 查询更准 | `encoder: clip`（真开放词汇）；调 `query.min_score` |
| 定位更准 | `segmenter: sam`；调小 `voxel_size`；多视角走 §3.3 的真实全景（旧的"虚拟相机"重渲染链路已删，收益从未被真实数据验证） |
| 关系判断更敏感 | 调 `reasoning.relations` 的 `adjacent_gap` / `axis_ratio` |

> ⚠️ 改任何阈值后跑 `pytest tests/test_reasoning.py`，
> 尤其 `test_relation_above_not_overridden_by_near`。
