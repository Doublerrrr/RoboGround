# 一、GRPO 家族

## Q1. GRPO 目标函数是什么？

**【背】**
GRPO 是 PPO 的**去 value-network 版本**：用"同一 prompt 采 G 个样本、取组内均值当基线"
代替 PPO 的 critic，然后照搬 PPO 的 clip 代理目标。

```
A_i = (r_i - mean(r_1..r_G)) / (std(r_1..r_G) + ε)          ← 组内优势

J(θ) = E[ (1/G) Σ_i (1/|o_i|) Σ_t  min( r_{i,t}(θ)·A_i ,
                                        clip(r_{i,t}, 1-ε, 1+ε)·A_i ) ]
       - β · D_KL(π_θ ‖ π_ref)

r_{i,t}(θ) = π_θ(o_{i,t}|·) / π_θ_old(o_{i,t}|·)            ← Importance Sampling 比率
```

**【展开】** 三个部件各自解决一个问题：
- **组内优势**：替代 value network，省掉一个与策略同规模的模型；
- **IS 比率**：样本是 `π_old` 采的，但我们要 `π_θ` 下的期望，必须做重要性加权；
- **Clip + min**：限制单步更新幅度，保证单调改进下界。

**【实测】** 我在 `src/roboground/rl/grpo.py` 手写了这套目标函数，
并把每个部件拆成可单测的纯函数；`tests/test_grpo.py` 有 38 个测试，
其中 8 组是"numpy 参考实现 vs torch 可微实现"的**数值等价测试**。

**【陷阱】** 分母 `|o_i|` 有两种放法：按**序列**归一化（GRPO 论文做法）
或按**全 batch 的 token 数**归一化。两种都有人用，
但必须在同一个实验里保持一致 —— 混用会让长短回答的权重无声漂移。

## Q2. 组内优势怎么估计？为什么要用组内均值？

**【背】**
把"这道题模型答得好不好"换成"**在这 G 个回答里相对好不好**"。
均值当基线、标准差归一化，得到零均值单位方差的优势。

**【展开】** 为什么这么做 work：
1. **省掉 value network**。PPO 要训一个 critic 估 `V(s)`，
   它本身也要训、也会引入偏差，而且要占一份显存。
2. **天然适配可验证奖励**。RLVR 只需要"答案对不对"，不需要学 value 函数。
3. **方差更小**。同一 prompt 的 G 个样本共享上下文，
   组内比较能消掉"这道题本身难不难"这个巨大的方差来源。

**【实测】** 我用假策略做了难度偏差对照（`--dry-run`）：

| 假策略正确率 | 组内优势退化比例 |
|---|---|
| 0.0（全错） | **87.5%** |
| 0.5（有对有错） | **6.2%** |
| 1.0（全对） | **93.8%** |

## Q3. Importance Sampling 在这里干什么？

**【背】**
样本来自**旧策略** `π_old`，但我们要优化的是**新策略** `π_θ` 的期望。
`r = π_θ/π_old` 就是把"在旧分布下算的期望"纠正回新分布的权重。

**【展开】** 为什么需要它：PPO/GRPO 是 **off-policy 的多步更新** ——
一次采样要做多次内层更新，更新几次之后策略已经偏离了采样时的策略，
必须用比率纠正。

**【实测】** 这个"必须"是可以量化验证的。
`--dry-run` 里对比不同的内层更新次数：

| `inner_epochs` | `mean_ratio` | `clip_frac` |
|---|---|---|
| 1 | **1.0000** | **0.0000** |
| 3 | **1.3771** | **1.0000** |

**`inner_epochs=1` 时策略根本没变过，比率恒为 1，clip 是一段死代码。**
≥2 次内层更新比率才会偏离 1 —— 这解释了"为什么 PPO 需要多次内层更新"。

## Q4. Clip 的作用是什么？Clip 的对象是什么？

**【背】**
**对象是"新旧策略的概率比"**，不是奖励、也不是优势。
作用是在比率偏离 1 太远时（说明新旧策略差太多、梯度方向不再可信）
把目标函数变成常数，**梯度为 0** —— 等价于"这一步先不学它"。

**【展开】** `min` 让它**悲观**，四条分支都要能说清：

| 优势 | 比率情形 | 结果 |
|---|---|---|
| A > 0 | `r` 超 `1+ε`（好动作概率涨太猛） | 截成 `(1+ε)·A` |
| A > 0 | `r` 低于 1（好动作概率在跌） | **不截**，继续给梯度 |
| A < 0 | `r` 低于 `1-ε`（坏动作概率跌太猛） | 截成 `(1-ε)·A` |
| A < 0 | `r` 高于 1（坏动作概率在涨） | **不截**，继续惩罚 |

一句话：**只在"策略已经很努力往正确方向走"时停止加码；
往错方向走时继续给梯度。** 这保证了单调改进的下界。

**【实测】【陷阱】** 我第一版把这条说反了 —— 注释写成"A<0 时不截断"，
被单测里 `obj = (1-ε)·A = -0.8` 而不是 `-0.5` 抓出来。
所以四条分支都写成了断言（`tests/test_grpo.py::test_clip_object_is_probability_ratio`）。

## Q5. KL 散度在这里怎么用？三种估计器有什么区别？

**【背】**
KL 项 `β·D_KL(π_θ‖π_ref)` 防止策略为了刷奖励**偏离参考模型太远**
（语言崩坏、输出重复）。设 `d = logp_ref - logp`：

| 估计器 | 公式 | 特点 |
|---|---|---|
| `k1` | `-d` | **无偏但方差大**，单样本可为负 |
| `k2` | `d²/2` | 恒非负、方差小，但**有偏** |
| **`k3`** | `exp(d) - 1 - d` | **无偏且方差最小**，实践默认 |

**【陷阱】** **k1 和 k3 都是无偏的**，差别在**方差**不在期望。
常见错误答案是"k3 无偏、k1 有偏"。正确推导：
因为 `E_{π_θ}[exp(d)] = Σ π_θ·(π_ref/π_θ) = 1`，
所以 `E[k3] = 1 - 1 - E[d] = E[-d] = KL`。

**【实测】** 我用蒙特卡洛验证了这一点（20 万样本、一对离散分布）：

```
真实 KL = 0.xxx
k1 均值 ≈ KL（相对误差 <3%），k3 均值 ≈ KL（同样 <3%）
但 k3 的标准差显著小于 k1  ← 这才是选 k3 的真正理由
```

k1 还有个直观毛病：单样本上会出现**负的 KL**，而 KL 本不该为负。

## Q6. GRPO 有哪些缺点？

**【背】** 四个，每个都能对上一条实测：

### ① 难度偏差（最本质）
一组 G 个样本**全对或全错**时 `std=0` → 优势恒 0 → **这道题贡献不了任何梯度**。
太简单和太难的题都是"白采"。

**【实测】** 上面那个对照表：全错 87.5%、全对 93.8% 的组退化，而 0.5 正确率只有 6.2%。

**处置**：过滤过易/过难的题（按历史正确率分层采样）、增大 G、
或改用**塑形奖励**让奖励不至于整齐地全 0。

### ② Token / Sequence 不一致
token 级比率下，同一序列里各 token 的比率可以一个 2.0 一个 1.0，
**clip 之后目标函数不再对应"整条回答的好坏"**。

**【实测】** `[2.0, 2.0, 1.0, 1.0]`（逐 token）vs `[1.414]`（整条序列）。

### ③ 稀疏奖励
如果奖励是二值的，早期几乎恒为 0 → 整组全 0 → 优势退化。

**【实测】** 我们基座模型的 3D 坐标误差是 **2.756 m**，
如果奖励设成"误差 <0.3m 给 1"，那基本恒为 0，完全学不动。
所以数值任务我改用**塑形奖励** `exp(-|Δ|/τ)`：
误差 2.7m 得 0.004、1.3m 得 0.074、0.4m 得 0.45 ——
**分都不高，但排序正确**，组内就有相对优势。

### ④ 冷启动
策略必须先有"**会做但不确定**"的分布，才能靠组内相对好坏优化。
基座模型没在目标格式上 SFT 过时，答案分布高度集中、不会探索。

**【实测·这个坑我踩得很实】** 我第一次跑 GRPO，
每一步的组内优势都是 0、`loss=0`、`grad=0`，一个字都学不到。两段原因：
1. **`top_k=1` 让采样退化成贪心** —— Qwen2-VL 自带的 `generation_config.json`
   里是 `{"temperature":0.01, "top_p":0.001, "top_k":1}`，
   `top_k=1` 只保留最高概率 token，而且**传 `temperature`/`top_p` 覆盖不掉**，
   必须显式给 `top_k=0`。后果是同 prompt 采 4 次得到**逐字符相同**的输出。
2. **冷启动** —— 修好采样后仍大量退化，因为基座没在输出格式上 SFT 过。
   改成从已有的 SFT LoRA 继续（**SFT → RL 两段式**）才正常。

修完后 `grad_norm` 从恒为 0 变成 **0.216~0.921**，组内退化率 **100% → 38%**。

## Q7. 回答变得单调、熵坍塌怎么处理？

**【背】** 四个手段，按"先诊断再下药"的顺序：

| 手段 | 原理 |
|---|---|
| **先查 reward** | 熵坍塌常见根因是**奖励被刷**：模型发现重复某个高分句式就能拿分。先看奖励分量分布，别急着调超参 |
| **clip-higher** | 对称 clip 下低概率 token 的比率容易被**上界**截住 → 永远拿不到正梯度 → 越来越确定。把上界放宽（0.28 vs 下界 0.2）给它留上升通道 |
| **高概率 token 裁剪** | 反过来，对**已经很高概率**的 token 不给梯度（或降权），防止"强者恒强" |
| **动态 KL 惩罚** | 熵低时自动加大 β，把策略推回参考模型附近 |

**【展开】监控什么**：训练时要一直盯着 `熵`、`clip_frac`、`mean_ratio`、
`reward` 分项。我把这些做成了 `TrainStats` 的**自动告警**：

```python
if 熵下降 > 0.5 nats:  → "熵坍塌：策略在变单调，建议开 clip-higher / 提高 KL 系数"
if clip_frac > 0.3:    → "clip 比例过高：新旧策略差异过大，降学习率"
if zero_adv_frac > 0.5 → "难度偏差：过半样本优势为 0，贡献不了梯度"
if 奖励没涨:            → "检查奖励设计（是否全 0 或全满）"
```

**【陷阱】** clip-higher 是放宽**上界**而不是下界 ——
放宽下界会让坏样本更容易被学，方向反了。

## Q8. GSPO 和 GRPO 的区别？

**【背】**
核心是 **Importance Sampling 的层级**：
GRPO 是 **token 级**比率，GSPO 是 **sequence 级**（长度归一化后整条序列共享一个比率）。

```
token 级   : r_{i,t} = exp( logπ_θ(o_{i,t}) - logπ_old(o_{i,t}) )
sequence 级: s_i     = exp( (Σ_t Δ_{i,t}) / |o_i| )        ← GSPO
```

**【展开】** GSPO 的三个动机，正好对应三个问题：

1. **Token/Sequence 不一致** —— 长度归一化后整条序列一个比率，
   目标函数重新对应"整条回答的好坏"。
2. **对 MoE 友好** —— MoE 的路由会让**逐 token 的方差被放大**
   （不同 token 走不同专家），序列级比率把方差摊平，训练更稳。
3. **长度归一化** —— 长回答的 log 概率和天然更负，
   不做归一化会让**长回答的比率系统性偏小**，然后被 clip 误伤。

**【实测】** 我实现里 `level="token"|"sequence"` 是个开关，
并且有单测保证"同一 batch 下两种层级给出的损失确实不同"
（否则说明开关没生效）：

```
序列内逐 token 比率：[2.0, 2.0, 1.0, 1.0]     ← 同一个回答里比率不一致
整条序列一个比率  ：[1.414]
```

# 二、LoRA

## Q9. LoRA 的低秩分解、初始化、Target Module

**【背】**
冻结原权重 `W₀`，只学一个低秩增量：`W = W₀ + ΔW = W₀ + BA`，
其中 `B ∈ R^{d×r}`、`A ∈ R^{r×k}`，`r ≪ min(d,k)`。

**初始化**：`A ~ N(0, σ²)`、**`B = 0`** ——
于是 `ΔW = BA = 0`，训练起点与基座**完全一致**（不能两个都随机初始化，
否则一开始就把基座能力破坏了）。

**Target Module**：最常见是注意力的 `q_proj / k_proj / v_proj / o_proj`。
想更强可以加 MLP 的 `gate_proj / up_proj / down_proj`（参数翻几倍）。
只加 `q,v` 是省参数的经典做法（原论文的做法）。

**【实测】** 我的两个 LoRA 都用 `q/k/v/o_proj`：
- SFT（Qwen2-VL-2B，r=8，α=16，4bit）：**9,232,384 可训练 / 0.42%**
- 从它继续做 GRPO：同样 **9,232,384 / 0.4162%**（数字一致说明 adapter 确实加载上了）

**【陷阱】** "冻结原权重"但**不要冻结到把输入也 require_grad=False** ——
我 RL 那次踩到：`logp_new` 如果 `.detach().numpy()` 了，
梯度根本传不回模型，训练会"看起来在跑、loss 也在变，但参数一动没动"。
所以加了 `test_torch_loss_actually_produces_gradients` 专门守这条。

## Q10. LoRA 的 Rank、Alpha 怎么设？

**【背】**
- **rank `r`**：低秩增量的秩，决定容量。常用 4~64。任务越"新"（离基座分布越远）需要越大。
- **alpha `α`**：缩放系数，实际生效的增量是 `ΔW = (α/r)·BA`。
  所以真正重要的是 **`α/r` 这个比值**，不是 α 的绝对值。
- **经验**：`α = 2r` 或 `α = r` 都常见。`α/r` 越大等效学习率越大。

**【展开】** 为什么用 `α/r` 而不是直接 `α`：
换 rank 做消融时，如果 α 固定，`α/r` 会跟着变，
于是"rank 的影响"和"缩放的影响"混在一起，实验没法归因。
写成 `α/r`（或让 α 随 r 等比变化）才能把 rank 的影响单独拎出来。

**【陷阱】** LoRA 的等效学习率还和 `α/r` 耦合 ——
调不动 loss 时不要只调 `lr`，两者要一起看。

# 三、注意力机制变体

## Q11. MHA / MQA / GQA / MLA / DSA

**【背】** 一句话概括整条演进主线：**都在压 KV Cache**。

先记住 KV Cache 的大小（面试常让当场推）：

```
KV cache = 2 × n_layers × n_kv_heads × d_head × L × dtype_bytes
           ↑(K 和 V)                              ↑序列长度
```

| 变体 | Q head | **KV head** | KV Cache | 思路 |
|---|---|---|---|---|
| **MHA** | h | **h** | 1×（基准） | 每个 Q head 配一套 KV |
| **MQA** | h | **1** | **1/h** | 所有 Q head 共享一套 KV |
| **GQA** | h | **g**（分组） | **g/h** | h/g 个 Q head 共享一套 KV，折中 |
| **MLA** | h | 压缩成 **latent** | **≪1/h** | 把 KV 压成低维向量，用时再投影还原 |
| **DSA** | h | 不变，但**参与计算的 token 少** | KV cache 不变，**算力降** | 稀疏注意力：只对 top-k 个 token 算 attention |

**【展开】**

**MQA vs GQA**：MQA 压得最狠（1/h），但**质量掉得明显**
（多个 Q head 被迫共享同一份 KV，表达能力受限）。
GQA 是工程折中：`g` 取 8 或 h/8 之类，实践中接近 MHA 质量、接近 MQA 速度。
**现在主流开源模型基本都是 GQA**（Llama 2/3、Qwen 系列）。

**MLA（DeepSeek-V2）**：思路完全不同 —— 不是减少 head 数，
而是把 KV **压成一个低维 latent 向量** `c_KV`，
推理时再上投影还原出 K、V。
关键在于它通过一个巧妙的**矩阵吸收**，把上投影融进 Q 侧和输出侧，
于是**推理时不需要真的还原完整 KV**，cache 里只存那个低维 latent。
收益比 GQA 更大，且质量接近 MHA。

**DSA（DeepSeek Sparse Attention，DeepSeek-V3.2-Exp 引入）**：
这一代不是压 cache，而是**减少参与 attention 的 token 数**。
用一个轻量的 **lightning indexer** 给每个 query 打分，
选出 **top-k** 个最相关的 token，只对这 k 个做 attention，
把复杂度从 `O(L²)` 降到 `O(L·k)`，从而大幅降低长上下文成本。

> ⚠️ DSA 比较新（2025 下半年），面试里如果对方提了，
> **以对方的定义为准**并说明"我理解是稀疏选择那一类"比较安全。

参考：[从 MLA 到 CSA：大模型 Attention 的"瘦身"与"闪送"](https://cloud.tencent.cn/developer/article/2699614)、
[DeepSeek V3.2 技术解读](https://www.baseten.co/blog/deepseek-v3-2/)、
[Optimizing DeepSeek-V3.2 on Blackwell GPUs](https://nvidia.github.io/TensorRT-LLM/1.3.0rc4/blogs/tech_blog/blog15_Optimizing_DeepSeek_V32_on_NVIDIA_Blackwell_GPUs.html)

**【陷阱】** 常见错误是把 MQA/GQA/MLA 说成"减少计算量"。
严格说它们主要减的是**显存与访存**（KV cache 是 decode 阶段的瓶颈，
decode 是访存密集型而不是计算密集型）。
真正减计算量的是 DSA 这类稀疏注意力。

# 四、推理引擎

## Q12. vLLM 的 Prefix Caching 为什么能提速？

**【背】**
Prefill 阶段会把 prompt 的每个 token 都算一遍 attention 并**缓存 K、V**。
如果两次请求的 **prompt 前缀相同**，那这段前缀的 KV 是完全一样的 ——
直接复用，**跳过重复的 prefill**。

**【展开】** 为什么收益大，要分清两个阶段的瓶颈：
- **Prefill 是计算密集型**：`O(L²)` 的注意力矩阵，GPU 打满；
- **Decode 是访存密集型**：每步只算 1 个 token，但要把整个 KV cache 读进来。

Prefix caching **省的是 prefill**，也就是省掉最贵的那一段。
在"前缀很长、后缀很短"的场景（多轮对话、固定 system prompt、
few-shot 示例），收益最大。

**【实现要点】**（追问时会问）
1. **按 block 做哈希**：vLLM 的 PagedAttention 把 KV cache 切成 block，
   对每个 block 的内容（含前缀 token 序列）算哈希，
   哈希相同就能复用，不需要逐 token 比对。
2. **需要 LRU 淘汰**：复用缓存不能无限增长，要有淘汰策略。
3. **要处理只命中一部分前缀**的情况：从命中的最长前缀之后开始 prefill。

**【陷阱】** 注意区分 **prefix caching** 和 **chunked prefill**：
前者省的是"重复计算"，后者是把长 prefill 切块与 decode 交错执行、
**降低首 token 延迟 TTFT 的抖动**。两者常一起用但目标不同。
